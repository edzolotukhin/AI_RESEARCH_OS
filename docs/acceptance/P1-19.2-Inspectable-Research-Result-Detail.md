## Summary

Adds `GET /research/{research_id}/result/detail` — a bounded, read-only projection
over canonical repositories for P1-20 UI inspection. Existing
`GET /research/{research_id}/result` is unchanged.

## Architecture

```
canonical repositories
  → ResearchRunResultQueryService.get_detail_for_run()
  → ResearchRunResultDetail (summary + detail payload)
  → ResearchResultDetailResponse
  → GET /research/{research_id}/result/detail
```

No new persistence. No write path. No Research semantics changes.

## Public endpoint

| Method | Path | Semantics |
|---|---|---|
| GET | `/research/{research_id}/result/detail` | Terminal only; 404 unknown; 409 non-terminal |

Bearer auth identical to P1-19.1.

## Detail payload

`detail` sibling object:

- `sources[]` — title, publisher, url, retrieval_status, evidence_count (no `content_text`)
- `evidence[]` — statement, `source_excerpt` from persisted Evidence, refs
- `findings[]` — statement, rationale, evidence_refs
- `insights[]` — statement, implication, finding_refs
- `report` — sections with bounded content, citation_registry (safe subset)
- `review` — issues[], quality_dimensions[], summary
- `truncation` — explicit truncation metadata

## Bounds

| Field | Limit |
|---|---|
| statement / rationale / implication | 800 chars |
| source_excerpt | 800 chars |
| review issue message | 1,000 chars |
| review summary | 2,000 chars |
| executive_summary | 4,000 chars |
| section content | 12,000 chars / section |
| total report content | 64,000 chars |
| collections | 200 items / type |

## Outcome behavior

| Outcome | Detail |
|---|---|
| APPROVED | Full report, findings, evidence, sources, approve review |
| NOT_READY | Readiness + evidence/sources; no invented report/findings |
| QUALITY_REJECTED | Latest report + review issues |
| EXECUTION_FAILED | Safe terminal fields only; no raw exceptions |
