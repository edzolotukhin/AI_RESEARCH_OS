## C. Canonical taxonomy

| `response_classification` | Fail-closed? | Meaning |
|---------------------------|--------------|---------|
| `incomplete_provider_output` | Yes | Provider incomplete/truncated |
| `empty_provider_output` | Yes | Completed (or unknown) + `len(content)==0` |
| `invalid_json` | Yes | Non-empty, no valid JSON |
| `root_type_mismatch` | Yes | Valid JSON, root ≠ object |
| `schema_contract_mismatch` | Yes | Root object fails `items` list contract |
| `valid_empty_result` | **No** | `{"items":[]}` |
| `valid_candidates` | **No** | `items` list length ≥ 1 |

`response_classification` ≠ persisted evidence yield.  
`failure_classification` remains the **stage-level** outcome (`no_candidates`, `grounding_rejected_all`, …).

---

## D. Precedence

1. incomplete / truncated (`was_truncated` or `incomplete_reason`)
2. empty visible content (`len==0`)
3. JSON validity
4. root type
5. Evidence schema (`items` list)
6. valid empty
7. valid candidates

**Whitespace-only** (`len>0`): `invalid_json` — consistent with existing parser (no containers / `json.loads` fail).

Incomplete + syntactically valid `{"items":[]}` or candidate payload → **`incomplete_provider_output`**, never valid-empty / valid-candidates.
