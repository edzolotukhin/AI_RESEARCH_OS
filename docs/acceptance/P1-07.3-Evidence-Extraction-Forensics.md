## D. Chunking audit

**Double chunking exists in production `extract_for_context` path:**

1. **Outer:** `build_need_fair_extraction_queue()` → `split_normalized_source_content()` on full source.
2. **Inner:** `ChunkedEvidenceExtractor.extract()` re-chunks the already-chunked text passed via `_extract_work_item()`.

When both layers share the same `chunk_chars` / `overlap_chars`, inner split on a bounded slice typically yields **one inner chunk** (degenerate pass-through), but the inner boundary is still executed and observable.

**Direct path** (`_extract_from_source` on full source text, targeted tests) uses inner chunking only.

## E. Coordinate / provenance audit

| Stage | Text coordinate system | Offset metadata |
|-------|------------------------|-----------------|
| Full source in DB | Original raw | N/A |
| Outer scheduler chunk | Absolute normalized (full source) | `original_normalized_start/end` |
| `_extract_work_item` | Chunk-local text replaces `source.content_text` | Absolute outer bounds attached |
| Inner `ChunkedEvidenceExtractor` | Re-normalized chunk-local | Local 0-based inner offsets (overwritten by service merge) |
| Service merge | Scheduler metadata wins | Absolute outer bounds in candidate metadata |
| `verify_grounding()` | Searches **chunk-local** `source.content_text` | Uses absolute outer start/end as search window |
| Persisted `source_locator` | Chunk-local normalized offsets | From successful grounding on chunk-local text |

**Forensic implication:** For multi-chunk sources, grounding search window may use absolute full-source offsets against chunk-local text. `verify_grounding()` fallback (unbounded search on chunk-local text) can mask bounded-window failures.

Diagnostics expose:
- `grounding_search_start/end` per work item
- `classify_grounding_failure()` detail: `excerpt_not_found`, `offset_mismatch`, `empty_excerpt`, etc.

## F. Grounding audit

**Contract (`grounding.py`):**
1. Normalize whitespace on source and excerpt.
2. Bounded search: `locate_excerpt(source_text, excerpt, search_start=chunk_start, search_end=chunk_end)`.
3. Fallback: unbounded search on same `source_text`.
4. Failure → `UngroundedEvidenceError`.

**Provenance contract (`provenance_validation.py`):**
- Filters `information_need_refs` to run-scoped allowed set.
- Empty after filter → `InvalidProvenanceError` (invalid need ref).
- Unknown design IDs → `InvalidProvenanceError` (provenance).

No grounding or provenance rules were changed in P1-07.3.

## G. Diagnostics added

- `workflow_run_id`, source counts, needs represented

### Per work item (`WorkItemTrace`)

- Source ID, checksum, information need IDs, queue index
- Outer chunk index/start/end/length
- Text length passed to extractor
- Grounding search window coordinates
- Extractor status, exception class/message
- Inner chunk observations (from `ChunkedEvidenceExtractor`)
- Per-candidate outcomes with rejection reason and grounding detail

### Persistence

Diagnostics included in `EvidenceExtractionSummary.to_dict()` under `"diagnostics"` when extraction completes without raising `EvidenceExtractionError`.

**Limitation:** When `EvidenceExtractionError` is raised (zero evidence), shared state is not written (existing behavior preserved). Diagnostics exist on the in-memory summary only if caller catches before raise; replay script uses `allow_empty_failure=False` path to capture them.
