## C. Proven pre-change EvidenceExpectation architecture

The domain model already existed and was first-class on `InformationNeed.evidence_expectation` (optional). Sufficiency already consumed it:

- `resolve_allowed_aspect_ids()` → explicit `required_aspects` or `__legacy_need__`
- `LlmSemanticSufficiencyAssessor` already put `evidence_expectation` into the user payload when present
- P1-07.11 fingerprint already included `evidence_expectation.to_dict()` and `allowed_aspect_ids`
- Domain `to_dict` omitted absent expectation; `from_dict` loaded old designs as `None`

The planner ingest path never requested, parsed, or constructed it:

- `RESEARCH_DESIGN_PAYLOAD_SCHEMA` and planner `system.md` omitted the field
- `InformationNeedDTO` had no field
- `ResearchDesignParser._parse_need` dropped any extra keys
- `ResearchDesignFactory._create_need` always built `evidence_expectation=None`
- API `InformationNeedResponse` omitted it

P1-07.10.2 used the real `PlannerAgent` on a brief-only n8n start. The live design therefore had 12 InformationNeeds and 0 EvidenceExpectations. That was not a fixture bypass.

## D. Exact gap that caused P1-07.10.2 to use `legacy_need`

Planner structured output never contracted EvidenceExpectation. Parser/factory discarded it even if the model had emitted one. Semantic sufficiency therefore called `resolve_allowed_aspect_ids()` on needs with `evidence_expectation is None` and evaluated `__legacy_need__`. Search coverage 12/12 and 66 evidence items could not make 11 evidenced needs SUFFICIENT against that synthetic target.

## E. Chosen canonical EvidenceExpectation model

Existing `domain.planning.evidence_expectation.EvidenceExpectation` remains canonical. No parallel quality model.

Fields used:

- `nature`: quantitative | qualitative | mixed
- `required_aspects`: non-empty canonical aspect IDs (planner-required; domain still allows empty for programmatic/legacy construction)
- `geography`, `timeframe`: optional applicability
- `minimum_independent_sources`: optional integer >= 1
- `requires_quantitative_evidence`: bool

This is a semantic contract (what evidence must establish), not an evidence-count threshold.

## F. Planner / research-design generation path

**Same structured planner call.** Nested `evidence_expectation` on each InformationNeed in the existing ResearchDesign JSON. No additional LLM stage. Deterministic offline planner synthesizes a mixed expectation per need from the brief-aligned need id.

## G. Planner schema / validation behavior

- Schema updated in `RESEARCH_DESIGN_PAYLOAD_SCHEMA` and planner system prompt.
- Parser requires a non-empty object with valid `nature` and non-empty `required_aspects`.
- `null`, `{}`, missing field, empty aspects, blank aspect IDs, invalid nature, non-bool `requires_quantitative_evidence` → `PlannerParserError`.
- Payload contract `accepts()` reuses the parser; malformed output retries via the existing 3×3 structured-output policy. Retry limits unchanged.
- Invalid output cannot silently become an empty-valid expectation. No fabricated fallback expectation.

## H. Domain invariants

- New planner designs: every InformationNeed that participates in readiness has a valid EvidenceExpectation.
- Legacy persisted designs: expectation may be absent (`None`).
- Distinction is presence/absence of the field after `from_dict`, not a fabricated upgrade.
- No repository-wide migration. No ResearchDesign schema version bump required.

## K. Exact semantic assessor path with explicit expectation

1. Hybrid evaluator builds deterministic signals.
2. Zero evidence → MISSING, 0 sufficiency LLM calls. Mode recorded as `explicit_expectation`.
3. Evidence present → `resolve_allowed_aspect_ids(need)` returns `expectation.required_aspects`.
4. `LlmSemanticSufficiencyAssessor` prompts with those IDs and includes `evidence_expectation` in the user JSON.
5. Policy/readiness merge unchanged: missing required aspects → INSUFFICIENT; all required aspects satisfied may be SUFFICIENT; quantity cannot override missing aspects.

## L. Exact `legacy_need` fallback path

`resolve_allowed_aspect_ids(need)` when `need.evidence_expectation is None` returns `("__legacy_need__",)`. Assessor scoped contract enters Legacy mode. Assessment `quality_contract_mode=legacy_need`.
