### Intended invocation


```text

```

Three-file merge order is undefined. Always apply acceptance **directly on base**.

## 3. Source-setting decisions

Base compose already interpolates `SOURCE_MAX_SOURCES_PER_RUN` default **30**, `SOURCE_MIN_SUCCESSFUL_SOURCES` **3**, coverage **1.0**. It does **not** set candidate slices → `ApplicationConfig` defaults **5 / 5**.

Profile B design requires candidate slices **3 / 3** (same pool shape as live `a0eade60`, not Profile C’s product-default 5). Inheriting 5/5 would silently change the designed envelope. Therefore the overlay **pins 3 / 3**.

`SOURCE_MAX_SOURCES_PER_RUN=18` must be pinned (base 30 is larger than Profile B).

`SOURCE_MIN_SUCCESSFUL_SOURCES=3` and coverage `1.0` match base defaults; they are pinned so API/worker cannot drift and so the overlay is self-describing. Coverage `1.0` is **not** weakened.

Lowcost `3/3/5` is **not** copied as a block: attempt cap is 18, not 5.

Who consumes what:

- **Worker** executes Collect sources + targeted acquisition via `build_source_acquisition_service` → `SourceAcquisitionBudget.from_config`. Worker **must** have source + LLM + targeted env.
- **API** loads `ApplicationConfig.from_env()` at process start. Planner runs on API during submit (operator runbook). Search/Evidence/Sufficiency/A/R/R run on the worker. Source keys are mirrored on API so the two processes cannot disagree if any API path builds a source budget, and so `docker compose config` is operator-inspectable.
- LLM stage caps are worker-only (same split as lowcost). Worker `create_execution_budget()` reads them.

## 4. Evidence-setting decisions

`EVIDENCE_MAX_LLM_CALLS=36` covers first-chunk exposure of 12 needs plus depth/targeted **pre-check** room on the Evidence stage cap.

Targeted extraction calls `extract_for_source_ids`, which **pre-checks** `assert_can_call("evidence")`. There is **no** separate targeted Evidence budget. Overlay introduces none.

`EVIDENCE_MAX_ITEMS_PER_SOURCE` is omitted (unenforced; not a limiting mechanism).

---

## 5. Sufficiency-setting decisions

`SUFFICIENCY_MAX_LLM_CALLS=36` matches P1-07.10: `12 × (1 + 2)` semantic assesses if all 12 needs are evidenced.

Hybrid evaluator: zero-evidence needs cost 0 LLM; evidenced needs cost 1 assess per `evaluate()`. The loop re-evaluates **all** evidenced needs after each targeted iteration.

Actual loop can attempt more than two gaps in one round. The cap—not the round bound—stops further assesses (`sufficiency_budget_exhausted`). That is current architecture; the overlay does not raise past 36.

Interaction (unchanged production behavior): readiness executor stage is `sufficiency`. Physical `generate()` during targeted extract is recorded against the **active stage**. Pre-check still uses the Evidence cap. So targeted extract LLM calls may increment **sufficiency** usage while still being blocked when Evidence is already at 36. Primary ready-after-initial-pass path is unaffected (`S≈12`). One residual targeted iteration still fits. Two full 12-need re-evals **plus** several extract-as-sufficiency calls can land near/over 36 → later live **CASE E**, not a silent raise.

## 6. Analysis / Report / Review

Current implementation happy path for 6 RQs:

- Analysis: 6 finding batches + 1 insight ≈ **7** (no structured-output retry wrapper). Cap **10**.
- Report: 6 section batches + 1 summary ≈ **7** first-attempt. Structured retries (max 3) and RQ corrections are residual. Cap **12** covers first-attempt + modest correction/retry, not worst-case 6×3.
- Review: `max_batches = REVIEW_MAX_CALLS`. Cap **3** = one batch + default structured attempts, or up to 3 first-attempt batches.

## 7. Global budget invariant

Worker `ExecutionBudget` (planner on worker, if any, counts; API planner typically does **not** share this object — operator runbook).

Downstream reserve while stage ∈ `{planner, search, evidence}`:

```text
reserve = S + A + R + V = 36 + 10 + 12 + 3 = 61
allowed_before_reserve = 120 - 61 = 59
```

Evidence cap 36 ≤ 59. Even after conservative planner 9 on the **same** budget: 9 + 36 = 45 ≤ 59. First brake at Evidence is `evidence_max_llm_calls`, not `downstream_reserve_exhausted`.

Then Sufficiency 36: reserve A+R+V=25 → allowed 95; after 9+36+36=81 ≤ 95. Analysis first call is permitted.

Full envelope 9+36+36+10+12+3 = **106 < 120**. Global is not the intended first brake.

If planner stays on API outside the worker budget, worker starts at 0 and has more slack.

### Pre-existing isolation test vs Profile B

`StageCapIsolationTests.test_evidence_cap_allows_analysis_first_call` uses product-like `global=100`, `evidence=50`, default S=20, R=20, V=7 → reserve 61 → only 39 Evidence calls before `downstream_reserve_exhausted`. That fixture is **not** Profile B. Profile B `36 < 59`. No budget-semantics patch.

## 11. Expected later live measurements

Do **not** run live in this phase.

**RUN:** `run_id`, `project_id`, `correlation_id`, workflow status

**SEARCH:** planned query count, unique URL candidates, URL attempts, successful sources, failed sources, skipped candidates, source coverage ratio, unique INs with acquired sources

**EVIDENCE:** sources processed, extractor attempts, raw candidates, persisted evidence, per-IN distribution, unique INs with evidence, `response_classification_counts`, completion metadata, Evidence budget stop reason

**SUFFICIENCY:** needs assessed; sufficient / insufficient / missing; confidence; missing aspects; calls; re-evaluations; budget stop reason

**LOOP:** loop count, targeted gaps, attempts, sources, evidence yield, improvement per loop, termination reason

**READINESS:** `ready_for_analysis`, blocking RQs, blocking INs, `research_outcome`

**ANALYSIS / REPORT / REVIEW:** status, calls, artifact / verdict

**GLOBAL:** stage usage if available, global budget stop reason, technical failures

### Later interpretation

| Case | Meaning |
|------|---------|
| A | Broad coverage + all needs sufficient + full pipeline → acceptance success |
| B | Broad coverage, semantic insufficiency → quality result; do not weaken readiness |
| C | 18 attempts still narrow IN coverage → Search fairness next |
| D | Sources cover needs, Evidence leaves many unextracted → Evidence allocation next |
| E | Broad evidence, Sufficiency cap stops reasonable eval → reassess S envelope |
| F | Ready but A/R/R hits caps → downstream profile correction |
| G | Global / downstream reserve preempts stage caps → envelope design defect |

Not-ready is not automatically a P1-07.10.1 failure.
