## E. Output-contract audit

**Does structured-output validate aspect IDs against allowed set?** **NO.**

`evaluate_raw_semantic_decision_payload()` validates:
- Required fields and types
- Array bounds (≤8)
- Non-blank string entries
- supported/missing overlap
- unresolvable + missing conflict

**Offline proven:** `supported_aspects=["payment terms"]` → contract **PASS** → normalizer **FAIL** (legacy path).

This is an intentional **boundary gap**: contract = transport shape; normalizer = domain fail-closed guard.

## F. Normalizer behavior

```python
required = evidence_expectation.required_aspects if expectation else ("__legacy_need__",)
unknown = (supported_set | missing_set) - required_set
if unknown: raise ValidationError(...)
```

- Rejects overlap supported∩missing
- Filters to required set only
- Adds implicit missing for unaccounted required aspects
- **No fuzzy matching, no label→ID mapping**

## K. Minimal fix recommendation — DO NOT IMPLEMENT

**Principle:** LLM must return canonical machine IDs exactly. No fuzzy label mapping.

### Phase 1 — Legacy path hardening (smallest, highest leverage)

1. **User payload:** add explicit `allowed_aspect_ids: ["__legacy_need__"]` for legacy needs
2. **System prompt:** reinforce "return ONLY IDs from allowed_aspect_ids; never return description text"
3. **Structured-output contract:** optional dynamic validator rejecting IDs ∉ allowed set (fail fast before normalizer)
4. **Observability:** persist `allowed_aspect_ids`, `returned_supported_aspects`, `unknown_aspect_ids` on failure

### Phase 2 — Expectation-backed path (when planner emits expectations)

- Same pattern with dynamic enum from `required_aspects`
- Live-accept expectation-backed path separately

**Do not:** weaken normalizer, add fuzzy matching, or map descriptions→IDs.
