## Status

**P1-07.4.1 RESPONSE-SHAPE OBSERVABILITY — PASS (OFFLINE)**

Observability-only instrumentation. No production semantic changes.

---

## A. Prior observability gap

P1-07.4 proved that for live run `b0cc1575-458f-458a-baf8-a97278340aa6`:

- 6 inner successes had `raw_candidate_count=0` with no way to tell whether the model returned empty `{"items":[]}` or usable evidence under a wrong key.
- 2 inner exceptions had `ValueError: LLM evidence payload must be a JSON object` with no persisted root type or response preview.

Raw provider `output_text` was not persisted.

---

## B. New diagnostic fields

Each **inner-chunk** observation now includes optional `response_shape`:

| Field | Meaning |
|-------|---------|
| `provider_response_received` | LLM returned a response object |
| `response_text_length` | Length of `response.content` |
| `response_preview` | Bounded output-only preview |
| `response_preview_truncated` | Whether preview was truncated |
| `json_container_count` | Root `{`/`[` containers found by JsonExtractor |
| `container_root_types` | Type of each extracted container |
| `parsed_root_type` | First container type, or fallback whole-text type |
| `parsed_root_keys` | Top-level object keys (max 20) |
| `expected_items_key_present` | Whether `"items"` key exists |
| `items_value_type` | Type of `items` value, or `"missing"` |
| `items_count_pre_filter` | Length when `items` is a list |
| `items_count_post_filter` | Candidates returned from item loop |
| `parser_succeeded` | Object root selected by parser |
| `rejected_*` counters | Per-filter rejection counts |
| `item_outcomes` | Bounded list of `{item_index, outcome}` |

Run-level counters added (existing counters unchanged):

| Field | Meaning |
|-------|---------|
| `inner_calls_completed` | Inner status `success` |
| `inner_calls_with_candidates` | Inner success with `raw_candidate_count > 0` |
| `inner_calls_zero_candidates` | Inner success with zero candidates |
| `inner_calls_exception` | Inner status `exception` |

---

## C. Item-filter taxonomy

| Outcome | When |
|---------|------|
| `rejected_non_object_item` | Item is not a dict |
| `rejected_missing_information_need_id` | Empty/missing need id |
| `rejected_unknown_information_need_id` | Need id not in run context |
| `rejected_empty_statement` | Empty statement after strip |
| `rejected_empty_source_excerpt` | Empty excerpt after strip |
| `rejected_invalid_confidence` | `float(confidence)` fails (exception still propagates) |
| `rejected_candidate_construction_error` | Other candidate construction failure |

Filtering decisions are unchanged from P1-07.4.

---

## D. Response preview safety

- Default max length: **800** characters (`DEFAULT_RESPONSE_PREVIEW_MAX_LENGTH`)
- Output-only: preview is taken from LLM response text, never source input
- Control characters normalized for readability
- Truncation explicit via `response_preview_truncated`
- No full provider response persisted
- No prompt or auth material captured

---

## E. Persistence path

Reuses P1-07.3 / P1-07.3.1 path:

```
LlmEvidenceExtractor → publish_response_shape()
ChunkedEvidenceExtractor → consume_response_shape() → InnerChunkObservation.response_shape
EvidenceExtractionService diagnostics → EvidenceExtractionError.summary
EvidenceExecutor → shared_state / failed task snapshot
WorkflowRuntimePersister → GET /workflow-runs/{run_id}/results
```

Path in results:

`task_results[].snapshot.shared_state.evidence_extraction.diagnostics.work_items[].inner_chunks[].response_shape`

## F. Example decision payloads

### Empty items (model semantic no-evidence)

```
queue=0 status=success root=object keys=[items] pre=0 post=0 preview={"items":[]}
```

### Root array (live q1/q2 class)

```
queue=1 status=exception root=array pre=null post=null exception=ValueError preview=[{...}]
```

### Wrong key alias

```
queue=2 status=success root=object keys=[evidence] items_key=false pre=null post=0
```

### Items filtered

```
queue=3 status=success root=object keys=[items] pre=4 post=0 unknown_need=3 empty_excerpt=1
```

## H. Payload-size considerations

- Preview capped at 800 chars
- Root keys capped at 20
- Item outcomes capped at 50 per inner call
- Aggregate counters preferred over full item payloads
- No statement/excerpt text in diagnostics

Typical inner-chunk `response_shape` adds ~1–2 KB per LLM call.

## I. Operator inspection method

After a controlled diagnostic E2E:

```powershell
# Fetch durable results
curl "http://localhost:8000/workflow-runs/{run_id}/results" | jq .

# Inspect inner-chunk response shapes
curl "http://localhost:8000/workflow-runs/{run_id}/results" |
  jq '.task_results[] | select(.task_id=="task-extract-evidence") |
      .snapshot.shared_state.evidence_extraction.diagnostics.work_items[] |
      {queue_index, inner_chunks: [.inner_chunks[] | {
        status: .extractor_status,
        root: .response_shape.parsed_root_type,
        keys: .response_shape.parsed_root_keys,
        pre: .response_shape.items_count_pre_filter,
        post: .response_shape.items_count_post_filter,
        preview: .response_shape.response_preview
      }]}'
```

Or read from persisted `p1-07-3-1-results.json`-style export after failure.
