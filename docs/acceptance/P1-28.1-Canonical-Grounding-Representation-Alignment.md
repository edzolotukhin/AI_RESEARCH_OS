# P1-28.1 — Canonical Grounding Representation Alignment

## Verdict

PROPERTY AF passes offline acceptance.

## Forensic root cause

P1-28 established a repeated grounding representation mismatch. Acquired HTML-derived Source text retained character references such as `&ndash;`, `&ldquo;`, `&nbsp;`, and `&#39;`. Evidence extraction returned readable rendered excerpts containing `–`, curly quotes, ordinary spaces, and apostrophes. The grounding validator collapsed whitespace but did not decode HTML entities, so semantically exact rendered excerpts failed its exact-substring check.

The P1-27.2 run produced 47 initial Evidence candidates and rejected 18 at grounding. All nine Pro-Consulting candidates were rejected. The comparison run repeated nine Pro-Consulting grounding rejects.

## Old representation pipeline

```text
raw HTML
→ strip script/style and tags
→ collapse whitespace (entities retained)
→ persist Source.content_text and checksum
→ normalize whitespace for chunking
→ encoded Source chunk shown to extractor
→ extractor returns rendered excerpt
→ whitespace-only normalization of Source and excerpt
→ exact substring lookup fails across encoded/rendered forms
```

The old representation did not decode HTML entities or normalize Unicode. It collapsed all Python-regex whitespace, including newlines and NBSP characters already present as Unicode. Matching remained case- and punctuation-sensitive.

## New canonical representation pipeline

```text
persisted Source.content_text (unchanged)
→ transient canonicalize_grounding_text()
   1. standard-library html.unescape(), once
   2. Unicode NFC normalization
   3. collapse Unicode whitespace runs to ordinary U+0020
   4. trim outer whitespace
→ chunk canonical text and assign canonical normalized offsets
→ show the same canonical chunk to extractor
→ canonicalize returned excerpt with the same function
→ exact, case-sensitive, punctuation-sensitive substring lookup
→ persist the extractor's readable excerpt unchanged
```

The single authoritative function is `canonicalize_grounding_text()` in `application/evidence/grounding.py`. The existing `normalize_source_text()` name delegates to it for compatibility. Both chunking and grounding already use that function, so they now share one representation without parallel decoding rules.

## Canonicalization rules

- HTML entities use Python standard-library `html.unescape`; no custom table or dependency.
- Named entities include `&amp;`, `&quot;`, `&apos;`, `&nbsp;`, and the standard HTML entity set.
- Decimal and hexadecimal numeric entities are decoded.
- Unicode is normalized to NFC. There is no transliteration or compatibility folding.
- All existing regex whitespace classes, including decoded NBSP, collapse to one ordinary space. Line breaks retain the existing equivalence to spaces.
- Case remains significant.
- Punctuation remains significant after representation decoding. No quote folding, dash folding, token replacement, edit distance, or fuzzy matching occurs.

## Fail-closed preservation

An excerpt passes only when its canonical representation occurs as one contiguous exact substring of the canonical Source representation. The following remain rejected:

- changed numeric values or percentages;
- changed company names;
- removed negation;
- inserted or omitted claim words;
- paraphrases;
- text assembled from non-contiguous spans;
- case-only differences not present in the Source.

No candidate is truncated, summarized, repaired, rewritten, fabricated, or semantically accepted.

## Persistence, offsets, hashing, and deduplication

Historical and new `Source.content_text` persistence is unchanged. No migration or backfill is required. Source content checksums, URL canonicalization, Source identity deduplication, and cross-arm provenance merging are unchanged.

Chunks and locators already used offsets into `normalize_source_text(Source.content_text)`, not raw HTML offsets. They now use offsets into the enhanced canonical representation. Tests prove each chunk equals the canonical Source slice identified by its normalized start/end values. No persisted raw-content offset contract changed.

Evidence persists the extractor-provided readable excerpt. Canonicalization is transient comparison behavior; encoded artifacts are not substituted into Evidence.

## Historical replay

Complete rejected excerpts were not persisted for all 18 P1-27.2 rejections. Bounded response previews provide two complete representation-only samples suitable for deterministic replay (Pro-Consulting-like entity punctuation and PizzaHouse-like entities/spacing). Both fail under the old whitespace-only representation and pass under PROPERTY AF. A UBA-like NBSP/entity fixture also passes, but the complete historical UBA excerpt is truncated and is therefore not counted as a direct historical replay.

Historical rejection inventory:

- `WOULD_NOW_ACCEPT_REPRESENTATION_ONLY`: 2 directly replayable complete samples.
- `STILL_REJECT_UNSUPPORTED`: 0 directly replayable historical samples.
- `UNOBSERVABLE`: 16 because complete rejected excerpts were not persisted.

This does not claim all historical rejections should pass. Negative forensic fixtures, including a changed Pro-Consulting forecast period, remain rejected.

## Domain-general acceptance

The same behavior is proven using:

- Ukraine pizza market report entities;
- New Zealand heat-pump text with `&amp;`;
- India UPI merchant text with apostrophe entities;
- German industrial-electricity text with NBSP and `&euro;`.

No domain, country, category, provider, or language term participates in production canonicalization.
