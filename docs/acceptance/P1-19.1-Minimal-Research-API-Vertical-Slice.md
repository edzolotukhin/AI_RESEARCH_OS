## E. Brief DTO

`PublicResearchBriefRequest` / `SubmitResearchRequest`:
title, business_question, objectives, geography, market, target_entities,
timeframe, constraints, deliverables, language, context, known_information,
exclusions + optional `project_id`, `correlation_id`, `source`.

Maps through existing `validate_research_brief`.

## F. Identity

`research_id == workflow_run_id` (alias only). Optional auto Project creation
from Brief title when `project_id` omitted.

## G. Submission

Creates/resolves Project, then calls existing `start_research(...)` path.
Preserves Idempotency-Key semantics. No duplicate orchestration.

## H. Execution status

`QUEUED` | `RUNNING` | `TERMINAL`

## I. Phase mapping (projected, not persisted)

QUEUED → PLANNING → RESEARCHING → EVALUATING → ANALYZING → WRITING → REVIEWING → COMPLETED

Active RUNNING/READY/WAITING tasks win by stage rank. Terminal always COMPLETED
(even when workflow FAILED). Product outcome is separate.

## J. Result behavior

Delegates exclusively to `ResearchRunResultQueryService.get_for_run`.
Adds `research_id` alias in API serializer.

## K–N. Outcomes

| Outcome | HTTP | Notes |
|---|---|---|
| APPROVED | 200 | report/review/artifact/provenance |
| NOT_READY | 200 | termination_reason + evidence/sources; no fake report |
| QUALITY_REJECTED | 200 | even if workflow FAILED; report inspectable |
| EXECUTION_FAILED | 200 | technical fail; no stack/secrets |

## O. Errors

| Case | Code | HTTP |
|---|---|---|
| unknown | `research_not_found` | 404 |
| active result | `research_not_terminal` | 409 |
| unsafe projection | `research_result_unavailable` | 409 |
