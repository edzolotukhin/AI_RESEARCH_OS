## C. Success semantics

| Field / status | Meaning |
|----------------|---------|
| `extractor_attempts` (run) | Incremented once per **work item** before outer `extract()` call |
| `extractor_successes` (run) | Incremented only when outer extract returns **non-empty** candidate list |
| `extractor_failures` (run) | Incremented only when **outer** extract raises (not swallowed by ChunkedEvidenceExtractor) |
| Inner `extractor_status="success"` | Inner `LlmEvidenceExtractor.extract()` returned without exception (may be `[]`) |
| Inner `extractor_status="exception"` | Inner exception (e.g. ValueError); **swallowed** by ChunkedEvidenceExtractor |
| Work-item `extractor_status="no_candidates"` | Aggregated candidate list empty; **not counted as run success or failure** |
| `extractor_exceptions` (run) | Only outer-level exceptions; **empty live despite 2 inner ValueErrors** |

**Conclusion:** Run-level `extractor_successes=0` with inner `success` is **expected naming** — run success means “at least one candidate returned to service,” not “LLM call succeeded.” Inner ValueErrors are **observable only in per-inner-chunk diagnostics**, not run-level failure counters.

## D. ValueError reproduction

**Raised by:** `LlmEvidenceExtractor._parse_payload()` when no extracted JSON root validates to a **dict**.

**Trigger conditions (proven offline):**

| Response shape | Result |
|----------------|--------|
| Root JSON array `[...]` | ValueError |
| Root JSON string | ValueError |
| Root `null` | ValueError |
| Root number | ValueError |
| Truncated / invalid JSON | ValueError |
| Root object `{"items":[]}` | Success, 0 candidates |
| Root object missing `items` | Success, 0 candidates |
| `{"items": null}` | TypeError (not ValueError) |

**Live q1/q2:** Consistent with **root JSON type ≠ object** (most likely bare array or non-object root). Raw response not persisted — exact shape **NOT PROVEN**.

**No provider structured-output schema** — only prompt text + `output_text` parsing.

## F. Structured-output contract audit

### Prompt-declared shape

```json
{"items":[{"statement":"...","source_excerpt":"...","information_need_id":"...","evidence_type":"direct_excerpt","direct":true,"confidence":0.8}]}
```

### Parser expectation

- Root MUST be JSON **object** (dict)
- Evidence list key MUST be **`items`** (not `evidence`)
- Item fields used: `information_need_id`, `source_excerpt`, `statement`, optional `evidence_type`, `confidence`, `direct`

### Discrepancies

| Layer | Issue |
|-------|-------|
| Prompt vs parser | Prompt shows `items`; no alias for `evidence` |
| Provider | No JSON schema enforcement; free-text `output_text` |
| Array root | Common LLM mistake; causes ValueError |
| Multi-root response | JsonExtractor may find later object after skipping non-dict roots |
