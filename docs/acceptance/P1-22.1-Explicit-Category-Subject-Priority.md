# P1-22.1 — Explicit Category-Subject Priority

## Verdict

PROPERTY Y passes offline acceptance. When a deterministic category subject is available, category preservation now leads source selection before P1-12 authority/statistical promotion and before the global source-attempt cap. This does not change the P1-22 diagnosis that the first observable P1-21.2 loss was provider retrieval/top-five candidate topology.

## Old ranking semantics

The prior selection key was:

1. P1-12 expectation/authority boost
2. existing relevance tier
3. cross-need coverage
4. broad topic score
5. geography penalty
6. provider rank
7. canonical URL

Broad topic score combined parent ResearchQuestion terms, InformationNeed terms, EvidenceExpectation aspects, and geography. It did not isolate the category subject. Consequently, Ukraine macro material could be labeled `direct` and receive P1-12 promotion without preserving the pizza category.

## New ranking semantics

The new selection key is:

1. category-subject tier
2. P1-12 expectation/authority boost
3. existing relevance tier
4. cross-need coverage
5. broad topic score
6. geography penalty
7. provider rank
8. canonical URL

The same category rank is used when choosing the best decision for a canonical URL discovered by multiple queries. It therefore applies before the unchanged global source-attempt cap.

## Category-subject derivation

Derivation uses the canonical `ResearchDesign` already supplied to source relevance:

1. Tokenize canonical ResearchQuestion text.
2. For multiple RQs, intersect tokens across every RQ.
3. For a single RQ, require candidate subject tokens to also occur in every child InformationNeed description.
4. Exclude geography, timeframe, EvidenceExpectation aspect terms, generic research/contract language, and numeric tokens.
5. Treat an empty or overly broad result (more than five tokens) as unavailable.

There is no fixed domain taxonomy and no pizza-specific keyword. Offline fixtures prove residential heat pump, UPI payments, and electricity retail subjects.

## Candidate signals

- `preserving`: at least one derived category-subject token occurs in candidate title, snippet, URL, or host.
- `not_preserving`: a reliable category subject exists but the candidate has no overlap.
- `unscored`: no reliable category subject could be derived; legacy behavior applies.

A `not_preserving` candidate cannot be classified `direct` solely from geography and generic overlap. It remains a bounded proxy fallback so zero category matches do not fabricate evidence or make Search fail closed.

## Fail-open behavior

If no ResearchQuestion text exists, no single-RQ child needs exist, the intersection is empty, or the derived set is too broad, category subject is unavailable. All candidates receive the neutral `unscored` category tier and retain the prior relevance/ranking behavior.

## P1-12 interaction

P1-12 remains unchanged within the category-preserving or fail-open population. Its expectation boost is suppressed for explicitly category-not-preserving candidates. Thus an official/statistical category source can still outrank a category blog, but an official macro source cannot cross the category tier.

## Source-attempt cap

Category rank is the first global sort component, before the unchanged cap of 30 canonical groups. A later category-preserving candidate therefore cannot be pushed outside the cap solely by earlier authority-promoted macro candidates. No cap or provider-result limit was increased.

## Initial and targeted-search parity

Both initial and targeted/remediation acquisition call the same `SourceAcquisitionService._select_groups()` and `selection_sort_key()`. Targeted Search continues to use parent RQ subject context and inherits identical category semantics without a separate implementation.

## P1-21.2 replay

Representative persisted Ukraine macro candidates from P1-21.2 were replayed against the pizza design. Zero were classified as category-preserving or category-direct. This does not create missing direct candidates and does not fix Tavily retrieval.

## Cross-domain proof

Offline cases derive and preserve subjects for:

- residential heat pump
- UPI payments
- electricity retail

Macro candidates for the matching geography remain category-not-preserving. No pizza token leaks into these contexts.

## Remaining risks

The derivation is intentionally conservative. Designs with unrelated RQs or inconsistent category wording fail open, and synonyms not lexically shared across RQs may not yield a subject. Candidate classification is lexical and can miss synonyms or be influenced by ambiguous terms. These are bounded false-negative/fail-open risks; no extra provider or LLM call was introduced.

The provider still may return no category-preserving result inside its bounded top five. PROPERTY Y cannot repair that retrieval loss; it only prevents category-preserving candidates, when present, from being displaced by category-irrelevant authority/macro candidates.

## Live-run decision

No paid/live run is required before implementation acceptance or commit. After review, commit, and push, one bounded paid/live re-acceptance is justified to test whether Tavily supplies category-preserving candidates in a new organic run. No paid/live Research was performed here.
