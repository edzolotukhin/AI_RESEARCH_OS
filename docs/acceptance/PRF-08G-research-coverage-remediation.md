**Root cause 1 — static global source ranking before cross-IN opportunity.** The existing ordered list could spend the eight-group cap on multiple IN3/IN5/IN6 sources while never trying an IN2 candidate. Rank/authority/category remain useful *within* a need, but an already represented IN should not categorically crowd out every unattempted material IN. The selection loop counted groups, not whether the resulting pages covered distinct needs. This is demonstrable from IN2's three `skipped_budget` decisions and the three acquired IN3-provenance pages.

**Root cause 2 — predictable unsupported format consumed scarce attempts.** The production HTTP retriever explicitly marks PDF bodies unsupported, yet two unambiguous `.pdf` URL candidates were selected for IN4 and counted against the same eight attempts. Unknown content types after redirects remain unpredictable, but the `.pdf` path case is knowable before fetch. The second candidate's foreign title being classified as direct geography is a separate ranking flaw: a target-geography mention in the result snippet can outweigh an explicitly foreign primary title. Neither observation proves that a better qualifying UK utilization page was present in the remaining candidate set.

**Root cause 3 — failed retrieval lacked a fair same-budget fallback opportunity.** The static order advanced past failed groups without prioritizing an uncovered IN's remaining candidate. In PRF-08F two IN4 failures and the cap left another IN4 proxy untried. Its viability is unproven, so this is a general orchestration/fallback defect, not a claim that a particular page would have made the run ready.

**Not diagnosed as a product defect from this run:** IN1/IN3 acquired pages yielded no claims for those specific needs; the saved source content/valid-empty extraction does not prove a missed grounded 50 kW+ comparison or operator-owned disclosure. IN1–IN4 have **zero raw mapped Evidence**, so PRF-08E temporal admissibility and PRF-08C lineage filtering did not cause their zero qualifying counts. Query diversity/wording cannot be fully audited for zero-result calls; no query-builder rewrite is justified. The conservative `insufficient_research` gate was correct and is not weakened.

## Bounded generic correction

1. The `SourceRetriever` port now offers a default-false `known_unsupported_url` capability. The current HTTP HTML/text/XLSX retriever identifies only an unambiguous `.pdf` URL path (including case-insensitive extension with query parameters) as known unreadable. Such a group is recorded as rejected with `retriever_known_unsupported_url` and does not consume an acquisition attempt. Redirects and unknown content types still go through the normal bounded retrieval path. Other retrievers keep their default behavior. This does **not** add PDF parsing or alter the result of a direct `retrieve()` call.
2. Eligible groups keep their established deterministic relevance ranking. At acquisition time, a group covering a never-attempted IN is chosen before a group covering only previously attempted INs; among those, a group for a still-uncovered IN precedes already-covered repeats. Original rank breaks ties. A failed fetch still consumes one attempt, stays recorded and leaves its IN uncovered; an available fallback can be chosen inside the **same** cap. Canonical URL grouping remains unchanged. Early coverage stop and minimum-success constraints remain unchanged.
3. A candidate whose **title** explicitly names a different known geography, while omitting the requested geography in the title, can no longer be promoted to `direct` solely because the blended title/snippet/URL text mentions the target. It is demoted to a fetchable `proxy` rather than categorically rejected. This uses the existing general named-place hints, not UK, China, DfT or domain exceptions.

The change makes **no increase** to search calls, acquisition attempt cap, Evidence LLM calls, structured retries, worker iterations or total LLM budget. It does not modify search-query isolation, Evidence provenance, temporal eligibility, data-lineage grouping, required RQ→IN mappings, structured extraction validation or readiness thresholds. Source-level diversity remains only an acquisition aim; it is never substituted for qualifying Evidence or independent lineage. Fair selection may alter which sources are examined under a fixed budget; it does not guarantee readiness.
