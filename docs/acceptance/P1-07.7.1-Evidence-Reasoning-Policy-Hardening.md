# P1-07.7.1 — Evidence Reasoning Policy Hardening

**Status:** IMPLEMENTED — OFFLINE ACCEPTANCE
**Branch:** `acceptance/live-desk-research-01`
**Date:** 2026-08-09
**Baseline live run:** `1202085f-f568-4779-8b35-8120d5178ec2`

---

## A. Motivation from live telemetry

Baseline Evidence stage (8 physical LLM calls):

| Class | Count | Notes |
|-------|-------|-------|
| `valid_candidates` | 1 | 3644 output / 3264 reasoning / 1421 visible / 3 candidates |
| `valid_empty_result` | 5 | `{"items":[]}` with ~320–576 reasoning tokens |
| `incomplete_provider_output` | 2 | 4096/4096/4096, visible 0, `finish_reason=length` |

Those incompletes are live-proven `max_output_tokens` exhaustion with no visible Evidence JSON. Evidence was the only LLM stage that omitted `reasoning_effort`, so the provider used its default reasoning spend.

## B. Previous Evidence policy asymmetry

Before this change:

- Planner / Sufficiency / Analysis / Report / Review: explicit `minimal`
- Search: not applicable
- Evidence: `generate(prompt)` with no `LLMGenerationOptions` → OpenAI `reasoning` key omitted

P1-07.7 documented that gap. This phase closes it only.

## C. Config field

`ApplicationConfig.evidence_reasoning_effort: str = "minimal"`

Same pattern as `planner_reasoning_effort`, `sufficiency_reasoning_effort`, `analysis_reasoning_effort`, `report_reasoning_effort`, `review_reasoning_effort`.

## D. Env override

`EVIDENCE_REASONING_EFFORT`

Loaded via `ApplicationConfig.from_env()` with `.strip().lower()`, matching other stages.

`docker-compose.lowcost.yml` is **not** modified. The next live run should prove the application default through diagnostics (`completion_configured_reasoning_effort=minimal`).

## E. Default minimal

This is a **stage-specific Evidence policy**, not a change to the global provider/model default.

- Global `LLM_MAX_TOKENS` remains 4096
- Evidence still does not set per-request `max_output_tokens`
- Other stages' reasoning defaults are unchanged

## F. Factory injection

```
ApplicationConfig.evidence_reasoning_effort
  → build_evidence_extractor(...)
  → LlmEvidenceExtractor(llm_client=..., reasoning_effort=config.evidence_reasoning_effort)
```

The executor does not own inference policy.

## G. Exact generate call change

Before:

```python
response = self._llm_client.generate(prompt)
```

After:

```python
response = self._llm_client.generate(
    prompt,
    options=LLMGenerationOptions(
        reasoning_effort=self._reasoning_effort,
    ),
)
```

No other generation options are added. Direct constructor default remains `"minimal"` so unit tests match production unless overridden.

## H. Provider-neutral mapping

Evidence depends only on:

- `LLMClient`
- `LLMResponse`
- `LLMGenerationOptions`

No OpenAI SDK types in `application/evidence` or `infrastructure/evidence`.

## I. OpenAI adapter mapping

Unchanged `OpenAIClient`:

`LLMGenerationOptions(reasoning_effort="minimal")`
→ `reasoning={"effort": "minimal"}`

`max_output_tokens` still comes from `LLMConfiguration.max_tokens` (default 4096) because Evidence does not override it.

## J. One-call invariant

Each logical Evidence extraction attempt still makes exactly one `generate()` call. No retry, fallback, or correction request.

## K. Budget / token invariants

| Setting | Status |
|---------|--------|
| `EVIDENCE_MAX_LLM_CALLS` live-desk compose | 8 unchanged |
| `LLM_MAX_CALLS_PER_RUN` | unchanged |
| `LLM_MAX_TOKENS` / Evidence `max_output_tokens` | unchanged (no per-request override) |
| Retry | none |

## L. P1-07.6 regressions

Taxonomy, precedence, completion metadata, schema fail-closed, `response_classification_counts`, stage `failure_classification`, and persister path are unchanged. Classification tests still pass with the new options argument.

## M. P1-07.5.1 regressions

Sufficiency / readiness path is unmodified. Semantic aspect-ID suites remain the regression gate.

## N. Remaining risks

- Whether `minimal` is enough to stop 4096/4096 zero-output incompletes is **not yet live-proven**
- Some `valid_empty_result` calls may still spend non-trivial reasoning tokens
- Invalid env values are stored after `.strip().lower()` with no raise — same as other stages (not silently mapped onto `REASONING_EFFORT_ORDER`)

## O. Next controlled live acceptance criteria

Compare against baseline `1202085f`. Do **not** define success as “zero incomplete calls” from one stochastic run.

Must prove:

`completion_configured_reasoning_effort = minimal`

on every Evidence inner call that received an `LLMResponse`.

Measure vs baseline:

- reasoning-token distribution
- `incomplete_provider_output` count
- visible output / `response_text_length`
- `valid_empty_result` / `valid_candidates` counts
- raw candidates and persisted evidence
- stage token usage

Collect per call: `queue_index`, `source_id`, `response_classification`, completion metadata fields, `response_text_length`, `parsed_root_type`, item counts, `raw_candidate_count`, `exception_class`.

No retry on that run. Same model, provider, token cap, and Evidence LLM cap as baseline.
