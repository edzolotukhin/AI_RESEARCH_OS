## B. Exact old acquisition semantics

After Tavily mapping, candidates carried `title`, `url`, `snippet` (`content`), `rank=list order`. Provider `score` was discarded.

`SourceAcquisitionService` grouped by canonical URL, then prioritized:

`(-InformationNeed coverage, provider rank, URL)`

Coverage was 1 for every group on the live 14 forensic run, so selection was provider rank + alphabetical URL. First 18 unique groups were fetch-attempted. Failed fetches consumed the attempt cap. There was no EE-aware or semantic post-retrieval eligibility check. Geography, required aspects, RQ topic, title, snippet, domain, and provider score did not influence selection.

Targeted remediation issued a new Search query (same `max_results=3`) and could re-select the same rank-1 URL. `existing_source_ids` was copied onto `TargetedResearchRequest` but never consumed by query building or acquisition.

## C. Root defect

Provider rank-1 junk entered acquisition directly. Generic IN wording (procurement / specs / GTM) matched unrelated pages. Zero-yield sources were retried for the same InformationNeed during targeted remediation, consuming the remediation source/Evidence budget with no new grounded Evidence.

### Deterministic relevance model

Tiers: `direct` / `proxy` / `ineligible` / `unscored`.

Topic anchors = RQ tokens ∪ IN/EE tokens ∪ geography tokens. Distinctive anchors exclude geography, digits, and generic contract words (procurement, specifications, strategy, …). Not a product taxonomy.

Candidate fields tokenized: title, snippet/content preview, URL/domain. Provider metadata is not tokenized.

- Generic contract-language overlap without distinctive parent topic → `ineligible` (positive unrelatedness).
- Zero distinctive overlap without that conflict signal → `unscored` (fetchable; absence ≠ unrelated).
- Topic overlap + matching geography token → `direct`.
- Topic overlap + broader/unknown/unrelated geo → `proxy` (still fetchable).
- EE=`None` → never `ineligible` (`unscored` or topic-aligned proxy/direct). Thin context → `unscored` rank fallback.

Sort key: `(-tier, -need_coverage, -topic_score, geo_penalty, provider_rank, canonical_url)`.

### Semantic signals

RQ question/rationale/objective_refs; IN description; EE `required_aspects` via existing `render_aspect_query_terms`; geography; timeframe; candidate title/URL/domain/snippet; provider rank. Provider score preserved in metadata, not a second ranking axis.

### RQ / IN / EE

EE remains the Sufficiency contract. Relevance only gates fetch. Generic IN descriptions inherit parent RQ topic tokens. No synthesized fake EE.

### Geography

Required token hit = direct. Scale/broad-region language = proxy. Other named-place hint without required token = unrelated (penalty only; does not auto-reject if topic-aligned). Unknown if no geo signal. Not Sufficiency geography semantics.

### Provider-rank role

Tie-break after tier / coverage / topic / geo penalty. No longer the sole effective relevance signal.

### Next-candidate fallback

Ineligible/exhausted groups are filtered before the attempt loop. Remaining groups in the same provider result set are considered in sort order until `SOURCE_MAX_SOURCES_PER_RUN` (or targeted `max_sources`) fetch attempts. No extra Search provider call. `max_results` unchanged.

Rejected pre-fetch candidates do **not** consume the attempt cap.

Fetch failures **do** consume an attempt slot (unchanged invariant). Initial acquisition with cap ≥ 2 can continue to rank-2 after rank-1 fetch failure. Targeted `max_sources=1` still allows only one attempt after filter; exhaustion/ineligible skip happens *before* that slot is consumed, so rank-2 can use the single targeted slot.

### Source exhaustion

Need-specific: all work_items for `(source_id, information_need_id)` completed a valid zero-yield (`extractor_status=no_candidates`, no technical inner failure) AND 0 persisted grounded Evidence. Invalid JSON, provider exception, budget_stop, pending, and grounding-rejected success are **not** exhaustion. Canonical URL identity. Not global. Non-zero Evidence is never exhausted here, even if Sufficiency remains PARTIAL.

### Legacy

EE=`None` remains searchable/selectable without exception.
