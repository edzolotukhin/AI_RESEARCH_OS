## Implemented narrow slice

`application/quantitative/dataset_limits.py` centralizes the existing 20 MiB source ceiling and new conservative 10,000-row / 200-variable / **100,000-cell combined** ceilings for the materialized, in-memory import path. `QuantitativeDatasetImportService` rejects oversize source bytes before parsing, and rejects empty, oversize or nonrectangular parsed data before any raw/row/manifest storage. UI refers to the same 20 MiB constant. XLSX rejects declared worksheet dimensions/cell counts before building its row lists. No source repair, truncation, accepted-record mutation, statistic recalculation or CSV support was added.

SAV now uses `pyreadstat.read_sav(..., metadataonly=True)` to check reported row and column counts before the full read. The installed `pyreadstat.read_sav` API supports this mode; the repository's `rb_reconciliation.sav` reports 4 rows / 9 columns. The importer-level checks reduce avoidable allocation, while the application-level post-parse check remains authoritative for both formats. XLSX still loads two workbook objects before inspecting dimensions; this is a remaining resource-safety gap, not a claimed complete defence against adversarial compressed workbooks.

Rationale: the current XLSX adapter materializes two workbooks and row lists; the SAV adapter materializes all rows, and the service fingerprints all parsed cells. The bounds are intentionally below arbitrary large survey extracts. These are protective V1 defaults, **not** a measured memory-capacity guarantee and not a complete compressed-workbook bomb defence. Parser/decompression/resource ceilings and exact empirical capacity should be validated before production rollout. A rejection applies to new imports only; historical dataset manifests remain readable. No present accepted fixture was shown to exceed the bounds.

The combined-cell bound matters: 10,000 × 200 would create 2 million cells and several additional Python/JSON copies. Limiting to 100,000 parsed cells allows either axis maximum only when the other is correspondingly smaller. This is a conservative operational envelope based on the inspected materialization/storage design, not a stress-tested worker maximum.

## Comparison / uncertainty audit (existing code, not a new QNT-02 capability)

`ComparisonStatisticsService` exposes exactly two QG methods, both `QG_1`, `qg-1` computation, strictly **unweighted**, two-sided with explicit `alpha`, minimum group base >=2 and `ALL_ROWS` filter. Both require current same-dataset/codebook result/view fingerprints and distinct groups. Missing outcome/group values are excluded from usable group N. `INDEPENDENT_TWO_PROPORTION_Z_TEST` uses two compatible cross-tab column percentages, a pooled standard error and two-sided normal p-value. `INDEPENDENT_WELCH_T_TEST` uses compatible numeric group means, sample variances, Welch degrees of freedom and two-sided Student-t p-value. Both persist difference, test statistic, p-value, significance boolean, group Ns, method/version and fingerprint. Zero standard error, invalid bases, mismatched inputs or incompatible/weighted views fail closed. **Neither method emits a confidence interval**; no CI is inferred. A non-significant p-value is a successful result. This inspection is not yet a known-answer acceptance for every QG method.

## Activation timing constraint

The current `QuantitativeUiService._create_quantitative_study_for_project` creates a **paused run before any dataset is uploaded**. Later `_analysis_safe_state` stores exact `dataset_record_id`, `dataset_version_id`, `dataset_fingerprint`, QC and weight identities; `_persist_activation_state` writes it before resume. A QNT-02 CMF implementation must therefore pin method/version at study/run creation and exact dataset/plan/weight authority at **analysis authorization**, then verify the same pin on worker restart. Requiring a dataset ID at initial empty-study creation would break the accepted user lifecycle. This is the central unresolved integration point; no fake dataset pin has been added.

### Limits and XLSX safety

The V1 structural maxima remain 10,000 data rows and 200 variables, independently; the **100,000 combined parsed-cell ceiling** bounds their product. This avoids the 2-million-cell combination implied by separate maxima, which would be multiplied by the current two-workbook XLSX load, Python row tuples, fingerprint serialization and protected JSON storage. The 20 MiB source-byte limit remains unchanged. These are conservative code-path bounds, not empirical worker-memory guarantees. SAV checks metadata-only dimensions before full read. XLSX now inspects central-directory ZIP metadata before either openpyxl workbook is loaded: at most 1,024 members, 64 MiB declared total uncompressed bytes, 32 MiB per member, no encrypted entries. The declared sheet dimensions/cell count are checked before row-list materialization. The checks reject obvious archive/decompression abuse; they do not prove protection against every malformed ZIP or all openpyxl allocations. No dangerous stress test was run.

### Deterministic results and readiness

Existing QA-QG/QD/QE/RC/RD computation and persistence remain authoritative. `CanonicalQuantResult` is a frozen **read-only projection** over their persisted `StatisticalResult` or `AnalyticalComparisonResult`, not a parallel statistics engine or second mutable result store. It binds exact method/analysis pin, dataset identity/checksums/schema/codebook, procedure/version, variable IDs, filter, weighting, source/unweighted N, denominators/weighted base, combined outside-base count where defensible, missing-value rules, precursor result refs, structured outputs, full specification parameters and deterministic provenance fingerprint. It refuses a different dataset or specification fingerprint. A missing-versus-filtered split is not invented where existing results expose only a combined base; comparison precursor refs remain resolvable through existing stored results. Computation wall-clock is not part of the deterministic fingerprint. Existing persisted result/manifest records retain their `rd-1` identities; this projection can be reconstructed from those records and the protected run/analysis pins.

Comparison capability matrix remains exactly QG: independent two-proportion pooled z-test and independent Welch two-sample t-test, both two-sided, strictly unweighted, minimum group base >=2 and explicit alpha. Both emit observed difference, test statistic, two-sided p-value and significant boolean; **neither emits a confidence interval**. The projection marks `P_VALUE_ONLY_NO_CI`; other statistics mark `NOT_PRODUCED`. A non-significant p-value is still a completed result. No other comparison, correlation or regression was added.

`QuantReadinessState` separates `INVALID_DATASET`, `INSUFFICIENT_DATA`, `UNSUPPORTED_PROCEDURE`, `COMPUTATION_FAILURE`, `READY` and `COMPLETED`. Missing eligible-base authority maps to computation/operational failure, not insufficient data. Unsupported procedure does not trigger a computation attempt; non-significance is never a failure. This foundation classifier is available through the Quant binding, but full study sufficiency/UX integration remains outside QNT-02 contracts.
