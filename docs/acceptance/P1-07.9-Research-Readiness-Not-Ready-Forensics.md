## 4. Readiness policy decision path

```
ResearchReadinessService.assess_and_apply
  → HybridResearchSufficiencyEvaluator.evaluate(design, all persisted evidence)
      per InformationNeed:
        evidence_count == 0 → MISSING / NO_EVIDENCE (no LLM)
        evidence_count > 0  → semantic assessor → SufficiencyPolicy → status
      RQ ready iff ALL its needs SUFFICIENT
      run ready iff ALL RQs ready
      targeted_research_required iff any PARTIAL/INSUFFICIENT/MISSING
  → if not ready and targeted required:
        ResearchLoopService.run_bounded_loop (low-cost: 1 round, 1 attempt/gap)
  → if still not ready:
        ResearchReadinessGate.apply_not_ready → skip analyze/report/review
```

Deterministic decision table:

| Condition | `ready_for_analysis` | `targeted_research_required` | Typical termination |
|-----------|----------------------|------------------------------|---------------------|
| All needs SUFFICIENT | true | false | `ready` |
| Any MISSING/INSUFFICIENT/PARTIAL, budget allows loop | false | true | loop may run |
| Actionable gaps remain, max rounds / no improvement | false | true then result reason set | `max_research_rounds` / `no_material_improvement` |
| Sufficiency stage cap hit | false | **false** (cleared) | `sufficiency_budget_exhausted` |
| All blocking gaps BLOCKED only | false | false | no targeted loop |

There is **no** total-evidence threshold. Priority is stored on the design but aggregation is **all-needs**, not priority-weighted.

Live path: initial not-ready + targeted required → 1 loop attempt on IN1 → re-eval still not-ready → sufficiency cap → `sufficiency_budget_exhausted` → `targeted_research_required=false` → gate skip.

## 11. Low-cost profile vs product semantics

The low-cost overlay made a 12-need Serbia microgreens brief structurally unlikely to become ready:

- 5 source attempts vs 12 needs and coverage ratio 1.0
- 8 Evidence calls on only 3 acquired sources
- 6 sufficiency calls ≈ 3 evidenced needs × (initial + post-loop)
- 1 gap round / 1 attempt

Product rule (all needs sufficient) is unchanged and stricter than “16 evidence items.” Low-cost limits prevented breadth; they did not invert a ready design into not-ready.

## 14. Product-correctness / architecture

Closest outcomes: **A + C + F**.

- Readiness semantics are **product-correct**. 16 items on three weakly matched sources do not cover a 12-need brief.

- Loop continuation after IN1 failed extract was stopped by sufficiency cap — consistent with P1-07.2.
- Observability is mostly sufficient for need-level “why,” insufficient for LLM usage accounting.

No justification to weaken readiness aggregation.
