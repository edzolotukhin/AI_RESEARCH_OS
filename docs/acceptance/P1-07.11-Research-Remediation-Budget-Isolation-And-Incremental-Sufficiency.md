## D. Previous budget architecture

Cited production path:

1. `TaskExecutor.execute` sets stage via `stage_for_executor` (`execution_budget_context.EXECUTOR_STAGE_MAP`).
2. Evidence task → stage `"evidence"`. Readiness/`research_quality` → stage `"sufficiency"` for the **entire** task.
3. `EvidenceExtractionService._next_evidence_budget_stop_reason` → `ExecutionBudget.assert_can_call("evidence")`.
4. Physical generate: `BudgetEnforcingLLMClient.generate` → `assert_can_call(get_execution_stage())` + `record_llm_call(stage)`.
5. `ProductionTargetedResearchRunner.run` → `extract_for_source_ids` with **no stage remap**. Pre-check used `"evidence"`; increment landed on `"sufficiency"` if generate ran.
6. After a full initial Evidence pass, pre-check failed with `evidence_max_llm_calls` → 0 targeted generate.
7. No partition, reservation, or call-purpose tag existed on `ExecutionBudget`.
8. Downstream reserve for stage `evidence` = S+A+R+V (treats Evidence as early-stage).

---

## E. Previous sufficiency re-evaluation architecture

1. `ResearchReadinessService.assess_and_apply` → `evaluate_for_context` → `HybridResearchSufficiencyEvaluator.evaluate`.
2. `_assess_need`: `evidence_count == 0` → no LLM (`MISSING` / `no_evidence`); else one `SemanticSufficiencyAssessor.assess` per evidenced IN.
3. `ResearchLoopService.run_bounded_loop` after each targeted attempt calls full `evaluate()` again → **all** evidenced INs re-billed.
4. Amplification (P1-07.10 / live 10.2): `S_calls ≈ evidenced_needs × (1 + targeted_reevals)`. Profile B sized `12 × (1+2) = 36`. Live: 11 evidenced × ~3 passes ≈ 33 plus retries → 36.
5. Assessments persisted in `shared_state["research_readiness"]` **without** evidence identity. `DeterministicSufficiencySignals.evidence_ids` existed only at eval time.
6. Evidence IDs are stable UUID PKs after persist; list order is deterministic (`ORDER BY id`). Dedup same key → same id.

## F. Chosen remediation-budget design

**Partition inside the existing Evidence stage**, not a second unrelated global stage counter.

```
EVIDENCE_MAX_LLM_CALLS                 = TOTAL Evidence envelope
EVIDENCE_REMEDIATION_RESERVED_LLM_CALLS = reserved targeted slice R
initial_allowance                      = TOTAL − R
```

- Initial purpose `"initial"`: may consume only `initial_allowance`.
- Targeted purpose `"remediation"`: may consume leftover initial **plus** reserved; total Evidence calls still `≤ TOTAL`.
- Non-targeted path cannot increment remediation counters or eat reserved.
- Targeted extract sets `set_evidence_call_purpose("remediation")` and stage `"evidence"` so physical generate bills Evidence, not Sufficiency.
- Remediation downstream reserve uses the **sufficiency** formula (A+R+V) because the call occurs inside readiness.

Meaning of `EVIDENCE_MAX_LLM_CALLS=36`: **A — total Evidence including initial + targeted**, partitioned rather than expanded.

---

## G. Why this design vs alternatives

| Alternative | Rejected because |
|-------------|------------------|
| Raise E/S/global | Forbidden; does not fix starvation shape |
| Separate `targeted_evidence` stage cap unrelated to E=36 | Two envelopes; Profile B would need a raise or a silent second budget |
| Keep billing targeted generate as Sufficiency | Leaves extract coupled to S cap (10.2 exhausted both) |
| Remap targeted to stage `evidence` without purpose + early-stage reserve | Mid-readiness `assert_can_call("evidence")` would apply S+A+R+V reserve and could false-stop (Profile B 72 ≥ 59) |
| Default R>0 in production | Would silently shrink initial Evidence for all existing configs/tests |

Least invasive: purpose tag + partition counters on the existing Evidence stage.

## H. Exact config semantics / defaults

| Key | Default | Meaning |
|-----|---------|---------|
| `EVIDENCE_MAX_LLM_CALLS` | `50` (unchanged) | **Total** Evidence LLM envelope |
| `EVIDENCE_REMEDIATION_RESERVED_LLM_CALLS` | **`0`** | Targeted-only floor reserved from that total |

`from_env` parses the new key as `max(0, int(...))`. Reserved is clamped to `≤ evidence_max_llm_calls` on the budget object.

Unset key ⇒ R=0 ⇒ identical to pre-P1-07.11 (initial may use the full envelope; targeted may use only leftover).

## I. Initial vs targeted Evidence accounting

Equations:

```
R = min(max(0, evidence_remediation_reserved_llm_calls), evidence_max_llm_calls)
initial_allowance = evidence_max_llm_calls − R
total_evidence_calls = initial_calls + remediation_calls
```

Stop reasons:

| Boundary | Reason |
|----------|--------|
| Initial hits allowance and R>0 | `evidence_initial_partition_exhausted` |
| Initial hits allowance and R=0 | `evidence_max_llm_calls` (legacy) |
| Targeted has no remaining total/leftover+reserved; R>0 | `evidence_remediation_budget_exhausted` |
| Targeted blocked and R=0 | `evidence_max_llm_calls` |
| Global | `llm_max_calls_per_run` (fatal; still wins) |
| Downstream reserve | `downstream_reserve_exhausted` |

Loop termination for remediation envelope: `evidence_remediation_budget_exhausted` (added to `BUDGET_CONTROLLED_TERMINATION_REASONS`). Clears `targeted_research_required`. Workflow completes; does not crash.

## M. Assessment state / persistence lifecycle

Reusable assessments live in run-scoped `shared_state["sufficiency_assessment_cache"]`:

```
information_need_id → {contract_version, fingerprint, assessment.to_dict()}
```

Not a second readiness model. `HybridResearchSufficiencyEvaluator` still emits a full `ResearchReadinessResult`.

Bound around each `evaluate()` via ContextVar; persisted after each pass; ContextVar restored so tests/runs do not leak.

Zero-evidence INs never store a semantic assessment; they remain deterministic `MISSING`.

---

## N. Idempotency / restart behavior

- Evidence rows + IDs survive → fingerprints can rematch.
- Cache is in `shared_state` and therefore in loop progress checkpoints / `task_results`.
- Worker resume with restored shared_state reuses matching entries.
- Old run with no cache / no fingerprint → `missing_prior_state` → normal assess (fail-safe).
- `ExecutionBudget` is still not checkpointed (pre-existing). Cache prevents duplicate semantic spend after resume; physical Evidence counters still reset on a new worker process (pre-existing gap, not widened).
- Idempotent replay of extract: same dedup key → same evidence IDs → same fingerprint → reuse.

---

## O. Selective reassessment algorithm

For each design IN, sorted `(research_question_id, id)`:

1. Deterministic signals (free).
2. If `evidence_count == 0` → `MISSING`, no LLM, do not reuse a prior semantic row.
3. Else compute fingerprint.
4. If cache hit (same IN id + fingerprint + contract version + parseable assessment) → return cached `InformationNeedAssessment`, 0 LLM.
5. Else call semantic assessor (1 sufficiency budget call), store cache.
6. Fail-safe: any parse/version/fingerprint mismatch → reassess. Never reuse on evidence **count** alone.

## P. Zero-evidence behavior

Unchanged: no semantic LLM. Repeated missing evals still no LLM. If evidence later appears, fingerprint is new → assess. All-IN readiness unchanged.

## Q. Targeted-loop behavior after fix

Before each targeted attempt:

1. Existing `sufficiency_budget_available()`.
2. New `evidence_remediation_unavailable_reason()` — if set, terminate with explicit budget-controlled reason; runner not called.

After extract: if remediation/total Evidence stop and `evidence_extracted == 0`, terminate (no spin).

If extract yields 0 without budget stop: incremental re-eval (0 extra S calls if fingerprints unchanged) → existing `no_material_improvement` / next gap logic.

Targeted generate is recorded as Evidence `remediation_calls`, not Sufficiency.
