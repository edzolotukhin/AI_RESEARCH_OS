## C. P1-25 assumption verification

The assumptions were verified on 2026-08-13 against the official [Tavily Search API contract](https://docs.tavily.com/documentation/api-reference/endpoint/search) and [credit documentation](https://docs.tavily.com/documentation/api-credits):

- `country` boosts/prioritizes results from the selected country; it is not documented as a hard filter.
- It is available only for `topic=general`, which is the current omitted/default topic.
- Values are lowercase country names from a provider enum. `ukraine`, `new zealand`, `india`, and `germany` are supported.
- `max_results` remains the maximum result count and defaults to five; this application explicitly retains five.
- Tavily prices Search by depth: current/default `basic` costs one credit; adding `country` has no separately documented surcharge. No billing call was made.
- No current request parameter is incompatible. `search_depth`, `topic`, `auto_parameters`, domains, time filters, result limit, and all other controls remain unchanged.

One unrelated provider-contract evolution was observed: current documentation shows Bearer authorization while this accepted adapter supplies the key in its existing JSON body. P1-25.1 deliberately does not alter authentication because that would violate single-variable isolation and existing offline contracts.

## D–E. Exact old and new provider request paths

Old:

`SearchQuery → PROPERTY AA provider_query_text fallback → Tavily {api_key, query, max_results} → normalization → PROPERTY Y / P1-12 ranking → acquisition`

New:

`SearchQuery.geography → deterministic resolver → Tavily capability set → optional country`
`SearchQuery → unchanged PROPERTY AA provider text → Tavily {api_key, query, max_results, country?} → unchanged normalization → unchanged PROPERTY Y / P1-12 ranking → unchanged acquisition`

Eligible request delta:

```text
BEFORE {query: <projection>, max_results: 5}
AFTER  {query: <identical projection>, max_results: 5, country: <supported country>}
```

The existing `api_key` field is omitted from this illustrative non-secret comparison. The actual adapter retains it unchanged.

## F. Country parameter semantics

Country is provider-side ranking context for general search. The application adds no local filter, candidate rejection, country-derived category classification, domain restriction, or post-response country preference. Result count remains bounded by the unchanged `max_results=5`.

## G–I. Resolver, fail-open behavior, and capability boundary

`application/sources/country_resolution.py` defines:

- `SUPPORTED_COUNTRY`
- `UNSUPPORTED_OR_UNRESOLVED`
- `AMBIGUOUS_OR_MULTI_COUNTRY`
- `NO_COUNTRY`

Resolution consumes only structured `SearchQuery.geography`. It normalizes punctuation/case and recognizes an explicit provider-supported country at a word boundary. It does not inspect query/category text, infer a country from a city alone, translate, geocode, map regions to countries, or guess neighbors. Multiple country matches are ambiguous. Global/missing geography has no country. Every non-supported state produces the old request.

The neutral resolver accepts a provider capability set; Tavily's documented enum remains in `TavilySearchProvider`. No Tavily vocabulary enters the Research domain model, no new provider framework was introduced, and an unsupported provider is unchanged because only the Tavily adapter invokes the capability.

## AP. Remaining risks

1. Deterministic name matching intentionally does not resolve abbreviations (`NZ`, `DE`), city-only geography, aliases, disputed territories, or nested region semantics; these fail open.
2. Provider-supported country values are an adapter capability snapshot and require maintenance if Tavily changes its enum.
3. Audit metadata exists only when at least one normalized candidate is returned; an empty/error response still lacks a durable per-call record. A future provider-only harness should retain bounded call-level diagnostics.
4. Current Tavily authentication style differs from today's documentation but is outside this isolated milestone.
5. Offline tests prove request construction, not that country prioritization improves recall.
