# P1-23.1 — Brief-Level Category-Subject Continuity

## Verdict

PASS. PROPERTY Z is implemented and proven offline. No paid/live Research, provider call, LLM call, commit, push, schema change, dependency change, or budget/cap change occurred.

## P1-22.2 live failure and addressed root cause

P1-22.2 proved that P1-21.1 could keep the parent ResearchQuestion in initial queries while still losing the category in 4 of 12 queries when generic or macro-oriented planner language did not repeat `pizza`. PROPERTY Y then had no reliable category tokens for those paths and failed open. The defect was architectural: initial Search, targeted/remediation Search, and deterministic Source relevance derived category context independently from lossy downstream planner text instead of sharing a Brief-level subject.

## Old and new category source

Old path:

`ResearchDesign RQ intersection -> _derive_category_subject_tokens() -> RelevanceContext`

Initial and targeted query builders separately used the parent RQ as subject context. There was no canonical Brief-level category source.

New path:

`ResearchBrief + ResearchDesign -> resolve_category_subject() -> CategorySubject -> initial Search + targeted Search + PROPERTY Y RelevanceContext`

The canonical source is `application/sources/category_subject.py`. The same resolved value is consumed by both query builders and deterministic candidate relevance. The Brief is passed from the existing `context.project.research_brief`; nothing is persisted.

## Deterministic derivation algorithm

1. Normalize and tokenize Brief `market`, `target_entities`, and `title` candidates.
2. Remove geography, timeframe/numeric, and domain-neutral generic research/market contract words.
3. Prefer a compact Brief market/entity candidate corroborated by the Brief business question.
4. Otherwise derive a compact phrase around a market/business-question category term.
5. Bound the category to at most five tokens.
6. If a Brief exists but no reliable category can be derived, return no category and fail open.
7. Only when no Brief is available, preserve compatibility through the prior conservative ResearchDesign intersection method.

No domain example (`pizza`, `heat pump`, `UPI`) is encoded in production logic.

## Search and remediation continuity

`SearchQueryBuilder.build_queries(..., brief=...)` and `TargetedSearchQueryBuilder.build_queries(..., brief=...)` inject the shared category context through `build_expectation_aware_query_text`. Existing phrase deduplication prevents redundant repetition. Both base targeted queries and semantic-directive variants receive the category. No extra query or provider call is created.

`SourceAcquisitionService` supplies the same Brief to initial query construction and to `build_relevance_context`. `ProductionTargetedResearchRunner` supplies it to remediation query construction. Thus PROPERTY Y ranks with the same category subject used to build the query.

## PROPERTY Y and P1-12 compatibility

PROPERTY Y remains a deterministic topical tier ahead of authority. The only change is the reliability of its category tokens. Within the same topical tier, existing provider/official/statistical ordering remains intact, so P1-12 still promotes stronger official/statistical sources without allowing category-irrelevant authority to outrank a category-preserving candidate.

## Fail-open behavior

Ambiguous Briefs produce no category tier rather than a guessed or over-broad subject. Candidate admission remains unchanged and existing ordering applies. Missing Briefs retain the legacy conservative design-derived behavior. No candidate is rejected solely by PROPERTY Z.

## Remaining risks and diagnosis

PROPERTY Z does not change the P1-22 conclusion that provider retrieval may still be the dominant live limitation: it cannot manufacture direct-category candidates that Tavily never returns. It ensures that category context survives planner decomposition and that existing category-preserving candidates are not disadvantaged because PROPERTY Y lacks its subject. Lexical deterministic derivation can fail open on terse or genuinely ambiguous briefs, and lexical candidate evidence can miss synonyms; those are bounded false-negative risks, not false-positive hard gates.

After review, commit, and push, exactly one organic paid/live re-acceptance is justified to measure whether the provider returns materially better candidates and whether the shared category signal changes live Source topology. No live run was performed for P1-23.1.
