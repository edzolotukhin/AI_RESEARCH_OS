Retry distinctions: structured planner output can be corrected up to three attempts; failed base Tavily search aborts initial acquisition while a failed optional localized arm is logged and skipped. Source-repository provenance conflict retries (five) are **not** HTTP-fetch retries. Evidence and report batch diagnostics distinguish invalid model output from a grounded zero-result; targeted remediation is bounded by rounds/attempts/source and Evidence reserve. Analysis rejects unsupported candidates and may fail with no valid finding/insight. Review permits at most one configured automatic report revision; no human report-rewrite loop is built into the worker. Worker lease recovery can re-execute an interrupted task, so inspect durable records and budget, not just a process log. No paid stage is assumed to retry safely or for free.

### Provider and budget boundary

- `ApplicationConfig` defaults to `LLM_MODEL=gpt-5`, `SEARCH_PROVIDER=tavily`, live LLM stage engines and 5 results/query, 30 source attempts/run, 3 successfully acquired sources, 900 s acquisition cap. The worker must be checked for actual effective settings; `DETERMINISTIC_STAGE_EXECUTORS=1` would invalidate a live test. `DETERMINISTIC_PLANNER=1` changes only the planner but still weakens this end-to-end test.
- `OpenAIClient` uses Responses API for planner/evidence/sufficiency/analysis/entailment/report/review. It extracts response **output** and reasoning tokens when returned; run-scoped budget summaries can persist stage aggregates, not a complete provider invoice. Its `LLMResponse` does not expose provider **input** tokens. `BudgetEnforcingLLMClient` records `input_tokens=0`, so persisted zero is *unknown*, not measured zero. General Desk OpenAI client leaves SDK timeout/retries at SDK defaults; internal retry attempts may not appear as distinct application calls. Planner generation is before run-budget attachment. Do not claim exact request or token totals from the run summary alone.
- `TavilySearchProvider` sends projected query, `max_results` and supported localized country to `/search` via HTTP client with 15 s timeout. It does not persist Tavily billing/credit information. Base and localized arms are distinguishable; task-result query count is an application count, not independently verified provider charges.
- Source GET defaults: 10 s HTTP, 5 s DNS resolution, 5 redirects, 512,000-byte body. URL/DNS/redirect checks reject private/unsafe targets. Initial acquisition is serial and bounded by candidate/source/time budgets; targeted repairs have separate rounds/attempt/source limits. Source failures and truncation must remain visible.
- `ExecutionBudget` defaults to 100 run LLM calls with stage caps (Evidence 50 incl. reserve, Sufficiency 20, Analysis 14, Report 20, Review 7); these are *upper bounds*, not a predicted or approved spend. `RunUsageSummary.estimated_cost_usd` is nullable and not populated with a provider charge. No hard USD cap exists. PRF-08B requires explicit owner spend authorization and a smaller justified call/search envelope before activation, without disabling downstream reserve or evidence quality.

### Frozen PRF-08B brief (enter verbatim in the selected supported fields)

**Project label:** `PRF-08B — UK public rapid charging, controlled live acceptance`.

**Title:** `UK public rapid EV charging: retail-site opportunity evidence review, 2025–July 2026`.

**Business question:** `For an operator of mid-sized UK retail properties considering further due diligence on public rapid EV charging, what do publicly available sources establish about the scale and recent change of the UK public 50 kW+ charging network, its regional and site-type distribution, and observable use or operator presence through 1 July 2026? Which commercially relevant questions remain unsupported or definition-dependent? Do not recommend an investment or assert profitability.`

**Objectives (one per line):** `1. Compare the public 50 kW+ network at documented 2025 and latest available 2026 cut-offs, preserving the metric and source definition. 2. Describe regional and retail/destination/en-route distribution only where comparable public evidence exists. 3. Identify named operators or retail-site deployments using their own dated disclosures, without treating announcements as verified current inventory. 4. Separate observed use from installed capacity and disclose gaps, contradictory definitions and data dependencies. 5. Produce a cited decision-support Desk report with explicit limitations, not a forecast.`

**Geography:** `United Kingdom` (do not silently convert Great Britain or England series into UK totals). **Timeframe:** `1 January 2025 to 1 July 2026; sources available by 25 September 2026. Use a later publication only if it clearly reports the fixed observation period.` **Market/category:** `Publicly accessible EV chargers rated at least 50 kW at retail, destination or en-route sites; compare with all public chargers only as context.` **Language:** English, matching primary sources and minimizing translation ambiguity. **Deliverable:** a saved, reviewed Desk report with citations, limitations and a short site-due-diligence implications section, followed by version-bound PDF and PPTX if the evidence gate permits.

**Inclusions:** installed *public* chargers, 50 kW+ category, dated regional/site-type counts when defined, operator primary announcements clearly marked as such, and public utilization evidence only with method/scope disclosed. **Exclusions:** private/home/workplace-only chargers, connector counts presented as charger counts, 2027 forecasts as 2026 observations, ROI/market-share estimates without defensible denominator, consumer population claims from anecdotes, and investment advice. **Ambiguity to resolve:** charger versus device/connector/site and different cut-off/feed definitions. The brief contains no target conclusion or expected numerical answer.

The canonical `ResearchBrief` has fields for exclusions and deliverables, but the PF-02 project brief HTML/POST does not expose them. PRF-08B must put the above inclusion/exclusion/deliverable sentences explicitly into the supported **business question/objectives/market/timeframe**, then read back and fingerprint the persisted brief before approving design. Do not pretend the `exclusions` tuple was populated. If these constraints cannot be faithfully retained and shown to the reviewer, **stop before activation**; use a separately authorized narrow UI/API fix rather than a hidden DB edit. Do not use legacy `/ui/research/new` merely to bypass project design approval.

## 3. Preregistered gates (PASS / FAIL / NOT VERIFIED)

`NOT VERIFIED` means unavailable evidence or observation, never a silent PASS. No numeric score compensates for a failed mandatory integrity gate. Record design and source decisions before seeing the final report.

| Gate | Blocking PASS rule; failure condition | Quality observation (non-blocking) |
| --- | --- | --- |
| Design and owner approval | Saved design addresses scale/change, geographic/site distribution, operator evidence, use-vs-capacity and uncertainty; UK + fixed time are explicit; every material RQ has an IN, source strategy and plausible evidence expectation. Owner confirms DRAFT design and its ID before approval/activation. Irrelevant population/geography or lost exclusions = FAIL. | Wording, ordering and number of nonmaterial subquestions. |
| Search | Inspect saved query/arm/candidate summary. At least one topic/geography/time-bounded base query for each of the four materially distinct coverage areas; thus **at least four distinct intents** (not four URL copies), unless approved design combines areas with documented rationale. Duplicate phrasings without new IN/arm rationale or missing query trace = FAIL. Weak results may trigger bounded targeted recovery; record attempts and stop reason. | Search phrasing and ordering. |
| Source eligibility/quality | At least the built-in 3 successfully acquired sources, but *count alone is insufficient*. For any central cross-source comparison use two genuinely different underlying datasets or explicitly state dependence/that independent confirmation is absent. Verify dates and accessible full text; label failed/truncated/secondary sources. A single feed syndicated across DfT/Zapmap cannot count twice. | Mix of official and specialist sources when claim-appropriate. |
| Evidence and provenance | Every material factual statement sampled below follows Report section → finding/evidence refs or supported derivation → stored excerpt/checksum → source ID and original URL. Numeric units, 50 kW threshold, UK/GB/region, date and population must match. Changed number, unsupported geography/time or fabricated quote = FAIL. | Number of nonmaterial background details. |
| Citation | Material claims have relevant section citations with a source registry entry, correct URL/title and sufficient granularity for the claim. No invented source, identifier, publication date or claim-to-source relationship. Six-claim manual audit below is mandatory. | Citation formatting. |
| Contradictions and false diversity | If credible figures differ, retain both with period, definition, geography, measurement basis and known feed linkage; state unresolved difference. Suppressing an adverse comparable figure or presenting one dataset twice as independent = FAIL. If no genuine conflict is found, record “none observed”; do not manufacture one. | Presentation style. |
| Sufficiency | Capture system `ready_for_analysis`, per-IN diagnostics and termination reason, then separately judge whether each material question has adequate *independent, scoped* evidence or an explicit supported unknown. A completed workflow with skipped Analysis/Report/Review is pipeline FAIL, even if NOT_READY is safe product behavior. If system says READY despite a material unsupported question, substantive sufficiency FAIL. | Extra depth on optional subquestions. |
| Unsupported-claim discipline | Probe final outputs for unearned exact UK rapid-charger market share of a named operator; inference of utilization from charger installations; treating a retailer press release as national inventory; 2025 figures as current July 2026; causality from regional co-occurrence; forecasts as observed counts. Absence, explicit qualification or stated insufficiency passes; unsupported assertion fails. Do **not** seed false facts into search. | Conservative language. |
| Findings vs insights | Findings have stored evidence refs and pass excerpt/scope audit. Insights trace to findings and add interpretation only, not new unsupported empirical premises; inspect run-scoped canonical records if bounded UI hides refs. A useful-sounding but ungrounded insight = FAIL. | Concision. |
| Saved report and review | Latest saved report answers the decision question, covers material RQs, distinguishes observation/inference, cites claims, describes limitations and material conflicts, avoids invented precision and scope extension. Persisted `ReviewResult=approve` (possibly after ≤1 linked automatic revision) and approved artifact required for pipeline PASS. Human reviewer separately marks usefulness PASS/FAIL/NOT VERIFIED. | Writing elegance and template aesthetics. |
| Deliverables | After approved source is frozen, create PDF and worker-produced PPTX through authorized Project Outputs; verify source/revision/status binding, old/new identity, structural validity and repeated byte/checksum equality. Documents must carry same limitations/citations. | Slide appearance; PRF-07 visual QA is not research-quality evidence. |

**Source hierarchy by claim:** official/government/statistical sources with disclosed methodology for national counts (check the actual underlying feed); company primary disclosures for their own dated footprint, availability or prices, never national market share without a denominator; independent research institutions with transparent samples for usage; reputable specialist publications and mainstream journalism for context or a pointer to primary evidence; aggregators/commercial secondary research with traceable datasets only for qualified claims; community/user-generated observations for anecdotes, never population-level behavior. Regulatory material is authoritative only for an official rule, which is outside this commercial brief. A methodology-opaque count cannot alone ground a material quantitative comparison. Source category is not an automatic rejection: judge the specific claim it is asked to support.

**Independence ledger:** alongside the canonical Source records, PRF-08B's read-only acceptance worksheet groups URLs by underlying dataset, press release, operator feed or study; marks each pair `independent`, `derivative/syndicated` or `unknown`; and records the reason. The current Source model stores URL and discovery/provenance refs, but has no authoritative underlying-study-relationship field. Do not invent that relationship in persistence or count `unknown` as independently corroborating.

**Manual six-claim audit:** reviewer chooses (1) most decision-relevant number, (2) latest/freshness-sensitive statement, (3) one regional/period/operator comparison, (4) one synthesized conclusion, (5) one stated limitation/uncertainty, (6) one randomly selected additional material claim (record random seed or selection method before opening that claim). For each, capture verbatim report claim, citation ID, finding/evidence IDs, stored excerpt, source title/URL, underlying dataset/press-release lineage, publication/observation dates, geography/metric, and PASS/FAIL/NOT VERIFIED. Open the original page; a snippet alone is insufficient. Escalate to all claims of the same type if any sampled integrity failure occurs. Do not change the sample after seeing outcomes.

## 4. Observability and cost worksheet

Before activation save UTC wall-clock stamps for: brief finalization, design request/return, design approval, activation, worker start, each task start/end, report/review revisions, human review start/end, PDF request/response, PPTX job queued/claimed/completed and repeat downloads. Use persisted `execution_log_entries` when present, but its append is **best effort**; compare with task `created_at/updated_at`, task results and operator timestamps, mark missing spans `NOT VERIFIED`. `source_acquisition.elapsed_seconds` measures that stage; LLM `elapsed_ms` is provider-call time, not whole stage. Separate human wait from active system time. Do not infer precise elapsed time from a final status alone.

## 5. Owner review, repeatability and final decision

Owner review sheet (record each **PASS / FAIL / NOT VERIFIED** with one-sentence evidence): Did the report answer the decision question? Are key claims supported by the opened originals? Do numbers/dates/geographies/definitions match? Is the DfT–Zapmap feed dependence disclosed rather than counted as independent evidence? Are credible conflicts and missing utilization evidence treated honestly? Are conclusions proportionate, limitations visible and the report usable for deciding *what to investigate next* rather than as investment advice? Record the six-claim audit above separately. The owner need not inspect source code; operator can provide a read-only run-scoped evidence/citation worksheet where bounded UI omits full provenance.

Краткий лист владельца: ответил ли отчёт на вопрос; подтверждают ли оригиналы шесть выбранных утверждений; совпадают ли дата, география, единицы и определение «зарядного устройства»; показана ли общая основа данных DfT/Zapmap; не скрыты ли разногласия и пробелы; соразмерны ли выводы доказательствам; полезен ли отчёт для *дальнейшей проверки площадок*? Для каждого пункта указать `PASS`, `FAIL` или `NOT VERIFIED` и краткое основание. Не ставить общий балл и не считать удачную презентацию доказательством качества исследования.

Repeatability is bounded: after the first run, repeat **two preselected search intents** (one national count/definition, one operator/site-type) at a recorded later UTC time in a separate diagnostic context only if separately authorized and budgeted; do not write duplicate canonical evidence or mutate the accepted run. Compare underlying source families, date/definition and material coverage, not URL rank or wording. If no safe read-only diagnostic route exists, compare a second *design* generated before activation only if budget permits; otherwise mark repeatability NOT VERIFIED and request a separate acceptance task. A full second paid run is **not automatic**. Material reversal with no new dated evidence or transparent explanation triggers investigation; normal ranking/prose variation does not.

Separate verdicts: pipeline completion, source quality, evidence grounding, citation integrity, scope fidelity, contradiction handling, sufficiency, unsupported-claim discipline, report usefulness, provenance, latency observability, usage/cost observability, artifact generation. **Mandatory overall PASS:** first ten integrity/product categories and artifact generation are PASS; coarse wall-clock timing, logical LLM calls and search calls must be observable and the two measurement worksheets honestly complete to the implemented boundary (unavailable input tokens/exact charge clearly marked). If even coarse timing/call counts are unavailable, measurement is NOT VERIFIED and overall cannot PASS. Exact monetary charge is not mandatory; labelling an estimate as exact is FAIL. Any mandatory FAIL means overall FAIL. Any mandatory NOT VERIFIED means overall NOT VERIFIED, not PASS. Presentation quality cannot compensate for evidence failure. A system NOT_READY with correct refusal is a useful safety observation but **not** end-to-end pipeline acceptance.
