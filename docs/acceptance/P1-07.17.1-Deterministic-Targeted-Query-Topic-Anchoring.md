## B. Old targeted-query path

```
TargetedSearchQueryBuilder.build_queries
  semantic_targets = request.missing_aspects or request.search_directives
  # when both empty → semantic_targets = ()
  build_expectation_aware_query_text(
    description=need.description,
    geography=need.geography,
    timeframe=need.timeframe,
    semantic_targets=semantic_targets,  # often empty under no_evidence
  )
  → query 0 = IN description + geo/time only
```

Parent RQ text was not consulted. Explicit EE required_aspects were ignored when `missing_aspects=[]`.

---

## C. Root defect

1. Empty `missing_aspects` (typical MISSING / `no_evidence`) dropped EE aspect phrases that initial 13.1 already embeds.
2. Methodological IN lead prose (e.g. “Triangulate…”) could dominate the only executed query under `TARGETED_MAX_QUERIES_PER_GAP=1`, losing parent product/domain context.

Not a provider bug; a deterministic query-intent regression vs the research contract.
