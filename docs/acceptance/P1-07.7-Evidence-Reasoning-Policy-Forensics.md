## C. Existing reasoning-effort contract

| Layer | Artifact | Contract |
|-------|----------|----------|
| Per-request options | `infrastructure/llm/generation_options.py` → `LLMGenerationOptions` | `reasoning_effort: str \| None`, `max_output_tokens: int \| None` |
| Ordered values | `application/structured_output/generation_policy.py` → `REASONING_EFFORT_ORDER` | `("minimal", "low", "medium", "high")` |
| LLM interface | `LLMClient.generate(prompt, *, options=None)` | optional options; Evidence omits them |
| Adapter | `OpenAIClient` | if `options.reasoning_effort` truthy → `request["reasoning"] = {"effort": ...}`; else **omit** key |
| Response echo | `LLMResponse.configured_reasoning_effort` | value sent, or `None` if omitted |
| Escalation helper | `_lower_reasoning_effort` | unknown strings rank above `high`; min index wins |

There is **no enum type** and **no runtime validator** rejecting unknown strings. Values are free-form `str` constrained by convention + `REASONING_EFFORT_ORDER`.

Config env mapping (all default `"minimal"` except Evidence which has **no field**):

| Stage | Config field | Env var |
|-------|--------------|---------|
| Planner | `planner_reasoning_effort` | `PLANNER_REASONING_EFFORT` |
| Sufficiency | `sufficiency_reasoning_effort` | `SUFFICIENCY_REASONING_EFFORT` |
| Analysis | `analysis_reasoning_effort` | `ANALYSIS_REASONING_EFFORT` |
| Report | `report_reasoning_effort` | `REPORT_REASONING_EFFORT` |
| Review | `review_reasoning_effort` | `REVIEW_REASONING_EFFORT` |
| Evidence | **absent** | **absent** |

## H. Recommended minimal implementation: P1-07.7.1

**A. Evidence-specific `reasoning_effort`** — first.

Ranked alternatives:

1. **A — Evidence `reasoning_effort=minimal` (config + extractor options)**
   Directly addresses the omitted-policy mismatch. Same pattern as every other LLM stage. Smallest blast radius.

2. **B — `max_output_tokens` tuning**
   May let truncated calls emit JSON, but q4 already spends 3264 reasoning of 3644 output. Larger cap likely increases cost without changing inference policy. Defer until after A is live-measured.

3. **C — Incomplete-output retry**
   Live run already at Evidence LLM cap 8. Retry with **identical omitted reasoning** likely repeats 4096/4096 zeros and burns remaining budget. Retry only after a cheaper first-call policy exists (and only under existing cap).

4. **D — Provider-native structured output**
   Larger coupling; parser/schema contract change; does not help if reasoning consumes the entire budget before any output item exists.

5. **E — Other**
   Prompt change / JSON salvage / global LLM defaults — out of scope and less targeted.

## I. Why retry is not first

Two incompletes already consumed full 4096+4096 with zero text. Cap was hit (`budget_stop_reason=evidence_max_llm_calls`). Retry without policy change = same expensive failure + fewer remaining calls. Classification already fail-closes correctly.

---

## J. Why max_output_tokens tuning is not first

Successful candidate call used 3264 reasoning tokens to produce 1421 visible chars. Incompletes used 4096 reasoning and 0 visible. Expanding the shared budget treats the symptom (budget size), not the cause (unconstrained reasoning policy). Cost risk is high.

---

## K. Why structured output is not first

Zero visible output means there is nothing for a schema constraint to bind. Structured output is a later contract-hardening option after reasoning spend is controlled.
