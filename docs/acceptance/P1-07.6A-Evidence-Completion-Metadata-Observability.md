## A. Scope

P1-07.6A propagates existing provider-neutral completion metadata from `LLMResponse` into Evidence inner-chunk `response_shape` diagnostics and proves persistence through the runtime result path.

**In scope:** capture and persist completion facts.
**Out of scope:** classification, retry, budget/token/model changes, parser changes (P1-07.6B/C).

---

## B. Architecture boundary

```
OpenAI Responses API response
  → OpenAIClient (provider-specific normalization)
  → LLMResponse (provider-neutral platform contract)
  → LlmEvidenceExtractor (capture completion metadata)
  → ResponseShapeDiagnostics (P1-07.4.1 + P1-07.6A fields)
  → InnerChunkObservation.response_shape
  → shared_state.evidence_extraction.diagnostics
  → WorkflowRuntimePersister / GET results
  → strict parser / grounding / provenance (unchanged)
```

No parallel provider-specific diagnostics contract was introduced.

## D. Diagnostic fields added

Added to `ResponseShapeDiagnostics` (persisted under `work_items[].inner_chunks[].response_shape`):

| Field | Semantics |
|-------|-----------|
| `completion_finish_reason` | Normalized completion status from `LLMResponse.finish_reason` |
| `completion_incomplete_reason` | Normalized incomplete cause from `LLMResponse.incomplete_reason` |
| `completion_was_truncated` | From `LLMResponse.was_truncated` — **not** inferred from malformed JSON |
| `completion_output_tokens` | Output token count when supplied |
| `completion_reasoning_tokens` | Reasoning token count when supplied |
| `completion_max_output_tokens` | Request cap when supplied |
| `completion_configured_reasoning_effort` | Reasoning effort when supplied |

### visible_output_length

`response_text_length` already equals `len(response.content)` and matches `LLMResponse.visible_output_length`.
**No separate `visible_output_length` field** is persisted — single source of truth retained for backward compatibility.

Completion fields are included in `to_dict()` when `provider_response_received=True`.

## E. Capture point

```python
response = self._llm_client.generate(prompt)
response_shape = ResponseShapeDiagnostics.from_llm_response(
    response,
    json_extractor=...,
    json_validator=...,
)
# → record_completion_metadata(response) inside from_llm_response
# → existing from_response_content(content) for shape analysis
# → existing _parse_payload(response.content)
```

Capture occurs immediately after `generate()` returns and before parsing. On parse exceptions, `publish_response_shape(response_shape)` still runs — metadata survives.
