## B. UI architecture

```
Browser (same origin)
  → FastAPI Jinja UI routes (/ui/*)
  → ResearchUiFacade (in-process)
      → start_research / ResearchStatusQueryService / ResearchRunResultQueryService
  → minimal vanilla JS (polling, form guard, evidence expand)
```

No React, SPA, WebSocket, separate frontend repo, or new persistence.

## D. UI routes

| METHOD | PATH | Purpose |
|---|---|---|
| GET | `/ui` | Redirect → `/ui/research/new` |
| GET | `/ui/research/new` | Brief form |
| POST | `/ui/research` | Submit brief → redirect |
| GET | `/ui/research/{research_id}` | Progress or terminal result |
| GET | `/ui/research/{research_id}/status.json` | Polling status |
| GET | `/ui/research/{research_id}/detail.json` | Terminal detail (409 if active) |

## E. Auth / credential architecture

Browser never receives Bearer token. Server resolves trusted credentials via
`UI_INTERNAL_API_KEY` env or test bootstrap (`container._test_api_key_plaintext`),
then calls in-process Research services as `AuthenticatedPrincipal`.

## F. Public API boundary

UI main flow uses `ResearchUiFacade` only:

- submit → `start_research` path
- status → `ResearchStatusQueryService`
- detail → `ResearchRunResultQueryService.get_detail_for_run`

No `/workflow-runs`, `/tasks`, `/reports`, `/evidence`, `/sources`, `/reviews`
calls from UI templates, router, facade, or `research.js`.
