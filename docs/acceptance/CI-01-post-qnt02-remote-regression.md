# CI-01 — Post-QNT-02 remote regression

Baseline: accepted and pushed QNT-02 commit `cba76895fb42a6ec6fa4a8653a3d4c5a9b11c289`, branch `acceptance/live-desk-research-01`, clean tracked/index state. GitHub Actions [run 36422445581](https://github.com/edzolotukhin/AI_RESEARCH_OS/actions/runs/36422445581) failed at the Unit tests step: **3,062 run, 17 failures, 13 errors, 150 skipped**. Subsequent PostgreSQL/API/worker/build steps were skipped by that workflow failure. The job log download endpoint returned HTTP 403, so the remote symptom inventory is limited to the owner-provided totals/examples and public job-step metadata; no remote rerun has occurred.

## Diagnosis

The common uploaded-SAV 422 was a **QNT-02 production regression caused by an unlisted optional dependency**. The newly added `pyreadstat.read_sav(..., metadataonly=True)` used pyreadstat's default pandas output mode; `requirements.txt` pins pyreadstat 1.3.5 but does not install pandas. On Windows, pandas 3.0.5 happened to be installed, masking the defect. In the existing Linux/Python 3.11 application image without pandas, the exact default-mode call raises `PyreadstatError: You requested pandas as output_format but cannot import pandas`. Replaying the prior call through the UI with pandas unavailable returned **HTTP 422**, body text **“Quantitative operation Unable to continue Dataset could not be imported safely”**. This is why the local accepted 3,087-test result did not expose the 422.

The minimal product correction selects `output_format="dict"` for the metadata-only header read, matching the already-existing full SAV read. The same Linux/Python 3.11 image then reports the expected 7 columns and 5 rows without pandas. Dimension checks and fail-closed upload behavior are unchanged. Regression tests cover direct SAV parsing and authenticated UI upload with pandas deliberately absent. The previously failing `_create_uploaded` module and its wrong-owner/non-Quant guard pass.

The clean-checkout audit revealed a **separate test-packaging error**, not another product regression: `tests/integration/postgresql/test_qnt02_method_pin.py` imported `_populate_fixture` and `SyntheticClient` from `test_q2_13a_temp_durable_outcomes.py`, which is explicitly ignored by `.gitignore`. That private module is present locally but absent in Actions, replacing five PostgreSQL test cases with one import-error case during unit-test discovery. The QNT-02 PostgreSQL test now uses a small tracked, synthetic design-aware fixture under `tests/fixtures/quantitative/`; no private benchmark file was staged. Its five real PostgreSQL cases passed on a separate loopback-only `ci01_test` database. No real provider calls occurred. This fixture also removes the need for any semantic client during pre-semantic analysis; assertions require zero semantic calls.
