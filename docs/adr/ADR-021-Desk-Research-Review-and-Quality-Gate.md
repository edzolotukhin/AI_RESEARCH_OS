# ADR-021: Desk Research Review and Quality Gate

## Status

Accepted — DR-07 implemented (pending owner acceptance)

## Context

DR-06 delivers a structured Report and draft Markdown Artifact per workflow run.
Successful report generation is not equivalent to product acceptance. DR-07 adds an
independent review and quality-gate layer before a run may reach `COMPLETED`.

## Decision

### Review vs Report vs Quality Gate

| Concept | Role |
|---------|------|
| **Report** | Generated research output (may be draft/revised) |
| **Review** | Independent assessment of report quality and support |
| **Quality Gate** | Authoritative verdict on product readiness |

The writer never self-approves. Review runs in `task-review-report` after
`task-write-report`.

### Durable ReviewResult

Append-only `ReviewResult` records store:

- run/design/report/artifact linkage
- `review_attempt`, `verdict` (`approve` | `revise` | `reject`)
- typed `ReviewIssue[]` and per-dimension status
- `review_method`, `deduplication_key`

Dedup identity: `(workflow_run_id, report_id, review_attempt)`.

### Deterministic vs semantic review

**Deterministic structural validators** (application-owned, authoritative for
structural checks):

- research-question coverage
- citation registry resolution
- section Finding/Insight support
- limitations presence
- contradiction Finding acknowledgment
- artifact checksum consistency

**Production semantic review** (`LlmReviewEngine`, `REVIEW_ENGINE=llm`):

- real LLM-backed structured review via `JsonExtractor` + `JsonValidator`
- one bounded request per report section (section content truncated to
  `REVIEW_MAX_CHARS_PER_SECTION`, default 8000 chars)
- flags probable unsupported/overstated claims, prose vs Finding/Insight
  inconsistency, hidden contradictions, missing caveats, weak RQ answers
- returns `ReviewIssueCandidate` records only; application assigns IDs,
  validates refs, normalizes severity, and computes verdict
- heuristic — **not** formal natural-language entailment proof

**Deterministic semantic reviewer** (`DeterministicReviewEngine`,
`REVIEW_ENGINE=deterministic`):

- explicit tests/smoke only; never silent production fallback
- missing LLM client with `REVIEW_ENGINE=llm` fails at composition/invocation

### Verdict policy

Application computes authoritative verdict:

- **APPROVE** — no major-severity issues
- **REVISE** — correctable major issues; bounded revision loop
- **REJECT** — fundamental brief/provenance failure

LLM issue candidates inform verdict; LLM does not choose final verdict directly.

`REVIEW_MAX_REVISION_ATTEMPTS` bounds writer/review loops (default 1).

### Report revision model

Immutable report revisions:

- `revision_number`, `previous_report_id`, `approval_status`
- dedup key includes revision number
- one draft artifact row updated across revisions; status promoted to `approved` on APPROVE

### Artifact finality

| Status | Meaning |
|--------|---------|
| `draft` | Generated by writer; not final |
| `approved` | Passed quality gate |
| `rejected` | Failed quality gate |

`WorkflowStatus.COMPLETED` requires review APPROVE.

### Workflow DAG

```
collect sources → extract evidence → analyze → write report → review report
```

### API / n8n readiness contract

`GET /workflow-runs/{id}` exposes:

- `reviews_available`, `review_count`, `final_review_verdict`
- `final_artifact_available`, `final_artifact_id`

Polling semantics for external orchestrators:

| Terminal state | `status` | `final_review_verdict` | `final_artifact_available` |
|----------------|----------|--------------------------|------------------------------|
| Approved | `completed` | `approve` | `true` |
| Revise in progress / exhausted | `failed` | `revise` or absent | `false` |
| Rejected | `failed` | `reject` | `false` |

`GET /projects/{id}/reviews`, `GET /reviews/{id}` for owner-scoped review reads.

External orchestrators can poll terminal status and final artifact availability
without DB access. n8n production flow deferred.

### Recovery / concurrency

Review persistence uses dedup + optimistic retry (same pattern as DR-05/06).
Concurrent review attempts for the same report/attempt resolve to one durable row.

PF-04 crash window: if `ReviewResult` is persisted before task checkpoint, retry
reuses the durable review via dedup key and completes artifact finality without
duplicate rows.

## Consequences

- Desk research `COMPLETED` means quality-gate approval, not merely writer success.
- Draft artifacts exist before approval but are not exposed as final deliverables.
- Residual: semantic unsupported-claim detection is heuristic, not entailment proof.

## Deferred

Human review UI, PDF/DOCX/PPTX, n8n production workflow, vector DB/RAG, automatic re-search during review.
