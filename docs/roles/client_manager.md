# Client Manager

## Название

Client Manager

---

## Миссия

Преобразовать любой входящий запрос клиента в структурированный Project Brief, достаточный для дальнейшего проектирования исследования.

---

## Ответственность

### Отвечает за

- Прием запроса клиента.
- Анализ входящей информации.
- Извлечение ключевых данных.
- Проверку полноты информации.
- Формирование уточняющих вопросов.
- Создание Project Brief.
- Передачу Project Brief следующей роли.

### Не отвечает за

- Проектирование исследования.
- Выбор методологии.
- Расчет стоимости.
- Подготовку коммерческого предложения.
- Анализ результатов исследования.

---

## Входные данные

Client Request

Возможные источники:

- письмо
- PDF
- Word
- презентация
- результаты встречи
- заметки менеджера
- заполненная форма на сайте
- история переписки

---

## Используемые знания

### Business Rules

- Readiness Rules
- Правила квалификации проекта

### Knowledge Base

- Типовые структуры брифов
- Предыдущие проекты

## Business Rules

Определяет:

- достаточно ли информации;
- какие сведения отсутствуют;
- какие вопросы необходимо уточнить.

Если обязательной информации недостаточно, формирует список уточняющих вопросов.

---

## Использование LLM

LLM используется только для интеллектуальной обработки информации.

Основные задачи:

- анализ текста клиента;
- извлечение структуры из неструктурированных документов;
- выделение целей исследования;
- выделение исследовательских задач;
- определение целевой аудитории;
- определение географии;
- выявление ограничений;
- формирование краткого резюме проекта.

LLM не принимает бизнес-решения.

Все проверки выполняются Business Rules.

---

## Выходные данные

Project Brief

или

Project Brief + список уточняющих вопросов.

---

## Возможные решения (Decision)

READY_FOR_RESEARCH_DESIGN

Информации достаточно.

или

NEED_CLARIFICATION

Необходимо уточнение.

или

NEED_EXPERT_REVIEW

Сложный или неоднозначный проект.

---

## Передача следующей роли

Research Designer

---

## Критерии качества

Project Brief должен:

- быть структурированным;
- не содержать противоречий;
- содержать всю обязательную информацию;
- быть понятным без обращения к исходному письму клиента.

---

## Тестовые сценарии

### Сценарий 1

Полный бриф клиента.

Ожидаемый результат:

READY_FOR_RESEARCH_DESIGN

---

### Сценарий 2

Отсутствует целевая аудитория.

Ожидаемый результат:

NEED_CLARIFICATION

---

### Сценарий 3

Отсутствует география.

Ожидаемый результат:

NEED_CLARIFICATION

---

### Сценарий 4

Большой PDF с описанием проекта.

Ожидаемый результат:

Корректно сформированный Project Brief.

---

### Сценарий 5

Противоречивый бриф.

Например:

в одном месте указана Украина,

в другом — Польша.

Ожидаемый результат:

NEED_EXPERT_REVIEW

---

## KPI роли

- Полнота извлеченной информации.
- Корректность Project Brief.
- Количество пропущенных обязательных полей.
- Количество проектов, успешно переданных в Research Designer без ручной доработки.
